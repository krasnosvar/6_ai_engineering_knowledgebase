# Примеры и эксперименты

Все три примера — профиль **CPU**: нужен только PyTorch из окружения курса,
без готовых весов и сети. Данные создаются прямо в коде. Команды выполняются
из корня репозитория. Перед запуском предскажи результат, после — объясни,
совпал ли он с прогнозом; затем измени одно условие.

`torch.manual_seed(42)` фиксирует случайные числа, поэтому на одной версии
PyTorch вывод повторяется. На другой версии или другом процессоре последние
знаки loss могут отличаться; выводы примеров от этого не меняются.
`torch.set_num_threads(2)` ограничивает число потоков CPU, чтобы пример не
занимал весь компьютер.

## 01_xor.py — сеть со скрытым слоем решает XOR

- **После урока:** [как записать нейросеть в
  PyTorch](../01_theory/02_pytorch_basics.md); задача XOR — из [урока о
  нейронах](../01_theory/01_neurons_and_backprop.md).
- **Идея:** скрытый слой с нелинейностью выучивает зависимость, которую одна
  прямая не разделяет.
- **Данные:** четыре точки XOR, `x` формы `(4, 2)` и номера классов `y` формы
  `(4,)` — те же тензоры, что в уроке о PyTorch.

```bash
uv run python 3_neural_networks/02_examples/01_xor.py
```

**Как читать вывод.** Loss на первом и последнем из 250 шагов (около 0.74 и
около 0.001) и предсказания `[0, 1, 1, 0]`. Предсказание — `argmax(-1)`:
номер класса с наибольшим logit в каждой строке. `assert` в конце проверяет,
что ответы совпали с `y`. Блок `with torch.inference_mode()` — применение
модели без записи графа, разобрано в [уроке о
переобучении](../01_theory/04_overfitting_and_validation.md).

**Что доказывает:** сеть `Linear → Tanh → Linear` подбирает веса под все
четыре точки XOR. **Чего не доказывает:** обобщения — проверять не на чем,
кроме тех же четырёх точек.

**Изменение.** Удали строку `nn.Tanh(),` в `nn.Sequential`. Предскажи: сможет
ли сеть из двух подряд линейных слоёв решить XOR? Проверка `assert` упадёт с
`AssertionError`. Перед этим будут напечатаны loss около 0.693 (это `ln 2` —
вероятности 0.5/0.5) и одинаковые предсказания для всех точек. Объясни, почему
два линейных слоя сворачиваются в один.

## 03_accumulation.py — накопление градиента из неравных частей

- **После урока:** [как организовать много шагов
  обучения](../01_theory/03_batches_and_training_loop.md), раздел о накоплении.
- **Идея:** градиент batch из 5 примеров совпадает с суммой градиентов частей
  2 и 3, если loss каждой части — сумма, делённая на общее число примеров 5.
- **Данные:** 5 случайных примеров по 3 признака, классы `[0, 1, 0, 1, 1]`.
  Две копии слоя `nn.Linear(3, 2)` начинают с одинаковых весов
  (`load_state_dict`).

```bash
uv run python 3_neural_networks/02_examples/03_accumulation.py
```

**Как читать вывод.** `PASS` означает, что `torch.allclose` нашёл градиенты
обоих способов равными с точностью до ошибок округления.

**Что доказывает:** правильное масштабирование делает накопление точным для
этой модели. **Чего не доказывает:** того же для слоёв вроде BatchNorm,
которые зависят от состава batch.

**Изменение.** В цикле убери `reduction='sum'` (останется среднее по части) и
замени `part_loss / len(x)` на `part_loss / 2`. Предскажи: совпадут ли
градиенты? Это ровно «среднее двух средних» из урока; `assert` упадёт с
`AssertionError`, потому что часть из 2 примеров получила лишний вес.

## 02_overfit.py — запоминание случайных меток

- **После урока:** [как отличить обучение от
  запоминания](../01_theory/04_overfitting_and_validation.md).
- **Идея:** train loss может упасть до нуля и без всякой закономерности в
  данных; validation loss это разоблачает.
- **Данные:** 128 примеров по 16 случайных признаков (`torch.randn`), классы
  0/1 выбраны случайно (`torch.randint`). 16 примеров — train, 112 —
  validation.

```bash
uv run python 3_neural_networks/02_examples/02_overfit.py
```

**Как читать вывод.** Таблица по эпохам: train loss падает от 0.725 до 0.000,
validation loss растёт от 0.686 до 2.878. Затем — эпоха с лучшим validation
loss (1) и итоговая accuracy: 1.000 на train, 0.464 на validation — около
монетки. Весь train помещается в один batch, поэтому одна эпоха здесь — один
шаг обновления.

**Что доказывает:** низкий train loss сам по себе не говорит об обучении
полезной зависимости. **Чего не доказывает:** что на настоящих данных
validation растёт с первой эпохи — обычно он сначала падает.

**Изменение.** Замени строку `y = torch.randint(...)` на `y = (x[:, 0] >
0).long()` — класс теперь зависит от первого признака. Предскажи: на какой
эпохе будет минимум validation loss и станет ли validation accuracy выше 0.5?
`assert` в конце рассчитан на случайные метки и может упасть — это ожидаемо.
Второй опыт: уменьши скрытый слой с 64 до 4 нейронов (`nn.Linear(16, 4)` и
`nn.Linear(4, 2)`) и сравни, как быстро падает train loss. Маленькая сеть
может не запомнить все 16 примеров, и `assert` упадёт уже из-за train
accuracy — запиши, какое условие не выполнилось и почему.
