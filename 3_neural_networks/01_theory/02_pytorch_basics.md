# Как записать нейросеть в PyTorch

В прошлом уроке мы считали нейрон, softmax и ошибку вручную, а про `model`,
`loss_fn` и `optimizer` в коде шага обучения только сказали, что они «уже
созданы». Сеть из сотен весов руками не посчитать: нужна библиотека, которая
сама хранит числа, выполняет операции и находит производные. В этом курсе это
**PyTorch**. К концу урока ты сможешь прочитать и написать код маленькой сети из

урока](01_neurons_and_backprop.md), градиент и шаг обучения из [урока о

## Тензор: числа, форма и тип

**Тензор** — массив чисел, с которым работает PyTorch. Создаётся из списка:

```python
import torch

x = torch.tensor([[0., 0.], [0., 1.], [1., 0.], [1., 1.]])
y = torch.tensor([0, 1, 1, 0])
print(x.shape, x.dtype)   # torch.Size([4, 2]) torch.float32
print(y.shape, y.dtype)   # torch.Size([4]) torch.int64
```

У тензора две важные характеристики. **Форма** (`shape`) — сколько чисел по
каждой оси: у `x` 4 примера по 2 признака. **Тип** (`dtype`) — какие это числа.
Точка в `0.` делает число дробным, и тензор получает тип `float32`; целые `0, 1`
дают `int64`. Признаки и веса — дробные, а номера классов для функции потерь —
целые: это пригодится ниже.

## Autograd: производные без ручного расчёта

Вернёмся к нейрону из прошлого урока: вход `[2,1]`, веса `[0.5,-1]`, свободный
член 0.2, выход `z=0.2`. Пусть правильный ответ 1, а ошибка — квадрат разности:
`loss=(z-1)²=(0.2-1)²=0.64`.

Посчитаем производные вручную по цепному правилу. `dloss/dz = 2(z-1) = -1.6`.
Выход зависит от веса через вход: `dz/dw₁=2`, `dz/dw₂=1`, `dz/db=1`. Отсюда
`dloss/dw = [-1.6·2, -1.6·1] = [-3.2, -1.6]`, `dloss/db = -1.6`.

Теперь то же самое в PyTorch:

```python
x1 = torch.tensor([2., 1.])        # один пример, не путать с x для XOR
w = torch.tensor([0.5, -1.], requires_grad=True)
b = torch.tensor(0.2, requires_grad=True)

z = (w * x1).sum() + b
loss = (z - 1) ** 2
loss.backward()
print(loss.item())    # 0.64000004529953 — это 0.64 с ошибкой float32
print(w.grad, b.grad) # tensor([-3.2000, -1.6000]) tensor(-1.6000)
```

`requires_grad=True` говорит: «следи за операциями с этим тензором, по нему
понадобится производная». `loss.backward()` проходит цепочку операций назад —
это и есть backpropagation — и кладёт результат в `.grad` каждого такого
тензора. Числа совпали с ручным расчётом: autograd не новая математика, а
автоматизация цепного правила. `.item()` превращает тензор, в котором ровно одно
число, в обычное число Python. Двухслойный пример с ReLU из [прошлого
урока](01_neurons_and_backprop.md) проверяется так же: autograd даст
`w₁.grad=-1` и `w₂.grad=-4`, как в ручном обратном проходе.

Запись операций, которую ведёт PyTorch, называют **графом вычислений**:
какие тензоры через какие операции дали `loss`. По нему `backward()` и
проходит назад. Граф занимает память, поэтому при простом применении модели
его запись выключают — это будет в уроке о переобучении.

Шаг обучения с learning rate 0.1: `w ← w − 0.1·grad`. Получаем `w=[0.5+0.32,
-1+0.16]=[0.82, -0.84]`, `b=0.2+0.16=0.36`. Новый выход
`z=2·0.82−0.84+0.36=1.16`, ошибка `(1.16−1)²=0.0256` вместо 0.64. Шаг по
градиенту уменьшил ошибку — ровно то, что делает оптимизатор.

## Слой nn.Linear

Вместо отдельных `w` и `b` берём готовый слой. `nn.Linear(2, 8)` — 8 нейронов,
каждый получает 2 входа:

```python
from torch import nn

layer = nn.Linear(2, 8)
print(layer.weight.shape)  # torch.Size([8, 2]) — по строке весов на нейрон
print(layer.bias.shape)    # torch.Size([8])    — по свободному члену на нейрон
print(layer(x).shape)      # x для XOR формы (4, 2) -> torch.Size([4, 8])
```

Слой вычисляет `x @ weight.T + bias` для всех примеров batch сразу: `.T` —
транспонирование (строки становятся столбцами), `@` — умножение матриц из [урока
о матрицах и тензорах](../../1_math_and_data/01_theory/12_tensor_operations.md).
Из формы `(4,2)` получается `(4,8)`. Обучаемых чисел `2·8+8=24`. Веса создаются
случайными — подбирать их будет обучение. `requires_grad` у них уже включён.

## nn.Sequential: слои по цепочке

Сеть для XOR — два слоя с нелинейностью между ними. Если данные проходят слои
строго по очереди, их собирают в `nn.Sequential`:

```python
model = nn.Sequential(
    nn.Linear(2, 8),   # (4, 2) -> (4, 8)
    nn.Tanh(),         # нелинейность, форма не меняется
    nn.Linear(8, 2),   # (4, 8) -> (4, 2): две оценки классов, logits
)
logits = model(x)      # вызов модели = прогон входа через все слои
```

Параметров: `24` у первого слоя и `8·2+2=18` у второго, всего 42.

## Своя модель: класс nn.Module

Когда вычисление не укладывается в простую цепочку (например, нужно сложить
выходы двух слоёв), модель описывают **классом**. Класс — это шаблон объекта,
который хранит свои данные (здесь слои) и умеет действия (здесь `forward`);
`class` и `self` с примером — в [минимуме
Python](../../0_lab_setup/python_minimum.md), подробнее — в
[Python-базе](https://github.com/krasnosvar/4_python_my_knowledgebase/blob/main/1_python/3_oop/01_theory/01_what_is_a_class.md).
Для чтения кода курса достаточно такой формы:

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()           # обязательная служебная строка
        self.hidden = nn.Linear(2, 8)
        self.out = nn.Linear(8, 2)

    def forward(self, x):            # что делать с входом
        return self.out(torch.tanh(self.hidden(x)))

model = Net()
logits = model(x)                    # PyTorch сам вызовет forward
```

`__init__` выполняется один раз при создании модели: в нём создаются слои, и
PyTorch запоминает их веса как параметры модели. `forward` описывает прогон
входа. Здесь те же операции, что в `Sequential` выше, но веса создаются
заново случайным образом, поэтому численные ответы могут отличаться.

## Функция потерь и оптимизатор

```python
loss_fn = nn.CrossEntropyLoss()      # logits и номера классов -> одно число
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

`CrossEntropyLoss` принимает logits формы `(batch, классы)` и целые номера
правильных классов формы `(batch,)`, внутри сам делает устойчивый softmax и
усредняет `-ln(p)` по примерам. `model.parameters()` передаёт оптимизатору все
обучаемые веса. **SGD** делает ровно тот шаг, который мы посчитали вручную: `w ←
w − lr·grad`. **Adam** — популярная замена: он подстраивает размер шага для
каждого веса по истории его градиентов.

Теперь шаг обучения из прошлого урока читается полностью:

```python
optimizer.zero_grad()            # убрать градиенты прошлого шага
logits = model(x)                # прогон: (4, 2) -> (4, 2)
loss = loss_fn(logits, y)        # одно число
loss.backward()                  # градиенты всех весов -> .grad
optimizer.step()                 # сдвиг весов против градиента
```

## Данные порциями: DataLoader

Когда примеров тысячи, их подают сети порциями — **batch**. `DataLoader` режет
набор на порции и при `shuffle=True` перемешивает их в каждой **эпохе** — полном
проходе по всем примерам набора:

```python
from torch.utils.data import TensorDataset, DataLoader

dataset = TensorDataset(x, y)                        # пары (признаки, класс)
loader = DataLoader(dataset, batch_size=2, shuffle=True)
for x_batch, y_batch in loader:                      # 4 примера -> 2 порции
    print(x_batch.shape, y_batch.shape)              # (2, 2) и (2,)
```

Сколько шагов в эпохе и как размер порции влияет на обучение — тема [следующего
урока](03_batches_and_training_loop.md).

## Типичные ошибки

- **Несовпадение форм.** `nn.Linear(3, 8)` для входа `(4, 2)` падает с `mat1 and
  mat2 shapes cannot be multiplied (4x2 and 3x8)`: слой ждёт 3 признака, а
  пришло 2. Первое число в `nn.Linear` — число признаков входа.
- **Дробные номера классов.** `CrossEntropyLoss` с метками `torch.tensor([1.,
  0.])` падает с `expected scalar type Long but found Float`: номера классов
  должны быть целыми (`int64`, он же `Long`).
- **Забытый `zero_grad()`.** Ошибки нет, но градиенты шагов складываются, и
  обучение идёт непредсказуемо — подробно в следующем уроке.

<details>
<summary>Разбор вопроса 1</summary>

Матрица весов `(64, 16)` — `64·16=1024` числа, плюс 64 свободных члена:
`1024+64=1088`. Именно такой слой стоит первым в лабораторной `02_overfit.py`.

</details>

<details>
<summary>Разбор вопроса 2</summary>

`x` — признаки, их умножают на дробные веса, поэтому нужен `float32`. `y` —
номера правильных классов для `CrossEntropyLoss`, они должны быть целыми
(`int64`). Если записать `y` с точками, функция потерь упадёт с ошибкой типа.

</details>

<details>
<summary>Разбор вопроса 3</summary>

Вызов `model(x)` PyTorch сам превращает в `forward(x)` (и выполняет при этом
служебную работу). Слои создаются в `__init__`, один раз: если создавать
`nn.Linear` внутри `forward`, при каждом вызове появлялись бы новые случайные
веса, и обучать было бы нечего.

</details>

остаток нужно отбросить, передают `drop_last=True`.
