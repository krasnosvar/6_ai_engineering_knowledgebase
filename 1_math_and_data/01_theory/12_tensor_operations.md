# Умножение матриц и формы тензоров

В [прошлом уроке](11_arrays_and_axes.md) мы научились называть оси
массива и вычислять средние. Теперь разберём, как перемножать матрицы,
менять форму данных и читать третью ось в пачке текстов.

## Матрица на матрицу

В [уроке о матрицах](04_matrices.md) `X @ w` умножал матрицу на вектор весов:
одно число на обращение. Если нужно несколько выходов — например, оценки для
четырёх команд поддержки, — весов становится матрица, и `@` перемножает две
матрицы. Каждый элемент результата — скалярное произведение **строки** первой
матрицы на **столбец** второй:

```text
A = [[1, 2],    B = [[5, 6],
     [3, 4]]         [7, 8]]

A @ B = [[1×5 + 2×7,  1×6 + 2×8],     [[19, 22],
         [3×5 + 4×7,  3×6 + 4×8]]  =   [43, 50]]
```

Правило форм: `(m, k) @ (k, n) → (m, n)`. Внутренние размеры `k` обязаны
совпадать — это длина строки слева и длина столбца справа. Таблица `X`
формы `(3, 2)`, умноженная на веса `(2, 4)`, даёт `(3, 4)`: три обращения,
по четыре оценки у каждого.

Не путай `@` и `*`. Звёздочка умножает элементы на одинаковых позициях:
`A * B = [[5, 12], [21, 32]]`. Это другая операция с другим смыслом.

## Изменение формы

- `reshape` меняет форму без изменения элементов: шесть чисел `0..5` можно
  уложить в таблицу `(2, 3)` — `[[0, 1, 2], [3, 4, 5]]`. Размер `-1` значит
  «сколько получится»: `reshape(-1, 1)` превращает вектор в столбец. Так
  делают для библиотек, которые ждут таблицу «примеры × признаки» даже при
  одном признаке.
- `ravel` вытягивает массив обратно в одну ось: `[0, 1, 2, 3, 4, 5]`.
- `np.vstack([a, b])` ставит таблицы друг под другом, складывая строки.
  Именно так в лабораторной объединяются train и test, чтобы показать
  ошибку подгонки преобразования по всем данным.

## Третья ось: пачка текстов

Позже модель будет читать текст по токенам — кусочкам слов, — и каждому
токену будет соответствовать вектор признаков. Тогда пачка текстов имеет
форму `(B, T, D)`: `B` — сколько текстов в пачке (batch), `T` — сколько
токенов в каждом, `D` — сколько признаков у токена.

Две фразы по три токена с двумя признаками дают форму `(2, 3, 2)`. Среднее
по оси 1 — по токенам — сворачивает `T` и оставляет по одному вектору на
фразу: форма `(2, 2)`.

```text
фраза 1: [[1, 0], [3, 2], [5, 4]]  → среднее [3, 2]
фраза 2: [[2, 2], [4, 4], [0, 0]]  → среднее [2, 2]
```

Но вторая фраза на самом деле короче: в ней два настоящих токена, а
`[0, 0]` — заполнитель, добавленный только чтобы выровнять длины в пачке.
Среднее настоящих токенов `[3, 3]`, а простое среднее по оси дало `[2, 2]`:
заполнитель исказил результат. Как исключить заполнители с помощью маски,
разберём в разделе о нейросетях — там это отдельное задание.

## То же в коде

```python
import numpy as np

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
print(A @ B)  # [[19 22] [43 50]]
print(A * B)  # [[ 5 12] [21 32]]
batch = np.array([[[1, 0], [3, 2], [5, 4]],
                  [[2, 2], [4, 4], [0, 0]]])
print(batch.shape, batch.mean(axis=1))  # (2, 3, 2), две строки по 2 числа
```

## Проверить понимание

1. Можно ли перемножить `(32, 10) @ (10, 3)`? А `(32, 10) @ (3, 10)`?
2. Почему простое среднее по оси токенов неверно для пачки текстов разной
   длины?

<details>
<summary>Разбор вопроса 1</summary>

Первое — да: внутренние размеры 10 и 10 совпадают, результат `(32, 3)`.
Второе — нет: слева длина строки 10, справа длина столбца 3. Вероятно,
вторая матрица записана повёрнутой: её транспонирование (строки становятся
столбцами) имеет форму `(10, 3)` и подходит.

</details>

<details>
<summary>Разбор вопроса 2</summary>

Короткие тексты дополнены заполнителями, чтобы все строки пачки имели
одинаковую длину `T`. Простое среднее делит сумму на `T` и учитывает
заполнители как настоящие токены, поэтому у коротких текстов результат
смещается к нулю. Нужно складывать только настоящие токены и делить на их
число.

</details>
