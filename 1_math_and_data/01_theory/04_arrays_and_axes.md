# Таблицы чисел целиком: формы, оси и стандартизация

В [первом уроке](01_vectors_and_linear_model.md) мы записали три обращения в
матрицу `X` и вычислили предсказания одной операцией `X @ w`. В [уроке о
данных](03_probability_and_data.md) выяснили, что среднее для подготовки
признаков считается только по обучающей части. Теперь соединим эти идеи:
научимся считать статистики сразу по всей таблице, приводить признаки к
одному масштабу и следить за формами массивов. Это понадобится в каждом
следующем разделе: в нейросетях данные идут пачками, а у текста появляется
третья ось — токены.

## Форма массива и его оси

Возьмём три обращения с двумя признаками — числом проверок и числом
перезапусков:

```text
X = [ [3, 2],
      [1, 0],
      [5, 1] ]
```

**Форма** (shape) массива — список его размеров по каждому направлению.
Здесь `(3, 2)`: три строки-обращения и два столбца-признака. Каждое такое
направление называется **осью** (axis). Ось 0 идёт по строкам — от одного
обращения к другому. Ось 1 идёт по столбцам — от одного признака к
другому. Число осей называют размерностью: у вектора одна ось, у таблицы
две.

## Сумма и среднее по оси

Операция «по оси k» сворачивает именно эту ось: складывает или усредняет
все значения вдоль неё.

- **По оси 0** складываем строки между собой и получаем по числу на каждый
  признак: `[3+1+5, 2+0+1] = [9, 3]`. Среднее по оси 0 — `[3, 1]`: в
  среднем три проверки и один перезапуск на обращение.
- **По оси 1** складываем внутри каждой строки и получаем по числу на
  каждое обращение: `[3+2, 1+0, 5+1] = [5, 1, 6]`.

Форма результата — исходная форма без свёрнутой оси: `(3, 2)` по оси 0 даёт
`(2,)`, по оси 1 — `(3,)`. Запись `(3,)` означает вектор длины 3 с одной
осью. Если свёрнутую ось нужно сохранить с размером 1, передают
`keepdims=True`: сумма по оси 1 тогда имеет форму `(3, 1)` — столбец, а не
строку. Зачем это нужно, увидим ниже.

## Broadcasting: операция между массивами разной формы

Чтобы вычесть среднее `[3, 1]` из каждого обращения, не нужен цикл. NumPy
сам «растягивает» вектор формы `(2,)` на все три строки — это называется
**broadcasting**, распространение:

```text
X - [3, 1] = [ [3-3, 2-1],      [ [ 0,  1],
               [1-3, 0-1],   =    [-2, -1],
               [5-3, 1-1] ]       [ 2,  0] ]
```

Правило: формы сравниваются с правого конца. По каждой оси размеры должны
совпадать, либо один из них должен быть равен 1 (или ось отсутствует) —
тогда эта сторона повторяется. `(3, 2)` и `(2,)`: справа 2 и 2 совпадают,
слева у вектора оси нет — вектор повторяется для каждой из трёх строк.

## Применение: стандартизация признаков

Число проверок и число перезапусков измеряются в разных единицах и с разным
разбросом. Многие модели обучаются лучше, когда признаки приведены к одному
масштабу. **Стандартизация** делает это для каждого столбца:

```text
z = (x - среднее столбца) / стандартное отклонение столбца
```

Стандартное отклонение мы считали в уроке о данных: корень из среднего
квадрата отклонений. Для первого столбца отклонения `0, -2, 2`, дисперсия
`(0+4+4)/3 = 8/3`, отклонение `≈1.633`. Для второго — отклонения `1, -1, 0`,
дисперсия `2/3`, отклонение `≈0.816`. Делим центрированную таблицу на
`[1.633, 0.816]` — снова broadcasting:

```text
Z = [ [ 0.000,  1.225],
      [-1.225, -1.225],
      [ 1.225,  0.000] ]
```

Теперь у каждого столбца среднее 0 и отклонение 1, и признаки сравнимы.

Главное правило из урока о данных здесь работает в полную силу: среднее и
отклонение — это **параметры преобразования**, их вычисляют только по
обучающей части, а к новым данным применяют те же числа. Новое обращение
`[7, 1]` превращается в `[(7-3)/1.633, (1-1)/0.816] = [2.449, 0]`. Значение
2.449 честно показывает: проверок необычно много по сравнению с обучением.
Если пересчитать среднее с участием нового обращения, это различие спрячется
внутри преобразования, а проверка перестанет быть независимой.

Стандартизация чувствительна к выбросам. Столбец `[1, 2, 3, 4, 5, 100]`
имеет среднее 19.2 и отклонение 36.2: после стандартизации обычные значения
сжимаются в узкую полосу от -0.50 до -0.39 и почти не различаются.
**Robust scaling** вместо среднего вычитает медиану (3.5), а делит на
межквартильный размах — ширину средней половины данных (здесь 4.75 − 2.25 =
2.5). Выброс почти не влияет ни на медиану, ни на этот размах, поэтому
обычные значения остаются различимыми (от -1.0 до 0.6), а выброс получает
большое значение 38.6. Квартили — это квантили 25% и 75% из урока о данных.

## Матрица на матрицу

В первом уроке `X @ w` умножал матрицу на вектор весов: одно число на
обращение. Если нужно несколько выходов — например, оценки для четырёх
команд поддержки, — весов становится матрица, и `@` перемножает две
матрицы. Каждый элемент результата — скалярное произведение **строки**
первой матрицы на **столбец** второй:

```text
A = [[1, 2],    B = [[5, 6],
     [3, 4]]         [7, 8]]

A @ B = [[1×5 + 2×7,  1×6 + 2×8],     [[19, 22],
         [3×5 + 4×7,  3×6 + 4×8]]  =   [43, 50]]
```

Правило форм: `(m, k) @ (k, n) → (m, n)`. Внутренние размеры `k` обязаны
совпадать — это длина строки слева и длина столбца справа. Таблица `X`
формы `(3, 2)`, умноженная на веса `(2, 4)`, даёт `(3, 4)`: три обращения,
по четыре оценки у каждого.

Не путай `@` и `*`. Звёздочка умножает элементы на одинаковых позициях:
`A * B = [[5, 12], [21, 32]]`. Это другая операция с другим смыслом.

## Изменение формы

- `reshape` меняет форму без изменения элементов: шесть чисел `0..5` можно
  уложить в таблицу `(2, 3)` — `[[0, 1, 2], [3, 4, 5]]`. Размер `-1` значит
  «сколько получится»: `reshape(-1, 1)` превращает вектор в столбец. Так
  делают для библиотек, которые ждут таблицу «примеры × признаки» даже при
  одном признаке.
- `ravel` вытягивает массив обратно в одну ось: `[0, 1, 2, 3, 4, 5]`.
- `np.vstack([a, b])` ставит таблицы друг под другом, складывая строки.
  Именно так в лабораторной объединяются train и test, чтобы показать
  ошибку подгонки преобразования по всем данным.

## Третья ось: пачка текстов

Позже модель будет читать текст по токенам — кусочкам слов, — и каждому
токену будет соответствовать вектор признаков. Тогда пачка текстов имеет
форму `(B, T, D)`: `B` — сколько текстов в пачке (batch), `T` — сколько
токенов в каждом, `D` — сколько признаков у токена.

Две фразы по три токена с двумя признаками дают форму `(2, 3, 2)`. Среднее
по оси 1 — по токенам — сворачивает `T` и оставляет по одному вектору на
фразу: форма `(2, 2)`.

```text
фраза 1: [[1, 0], [3, 2], [5, 4]]  → среднее [3, 2]
фраза 2: [[2, 2], [4, 4], [0, 0]]  → среднее [2, 2]
```

Но вторая фраза на самом деле короче: в ней два настоящих токена, а
`[0, 0]` — заполнитель, добавленный только чтобы выровнять длины в пачке.
Среднее настоящих токенов `[3, 3]`, а простое среднее по оси дало `[2, 2]`:
заполнитель исказил результат. Как исключить заполнители с помощью маски,
разберём в разделе о нейросетях — там это отдельное задание.

## То же в коде

```python
import numpy as np

X = np.array([[3, 2], [1, 0], [5, 1]])
print(X.shape)                               # (3, 2)
print(X.sum(axis=0), X.sum(axis=1))          # [9 3] [5 1 6]
print(X.sum(axis=1, keepdims=True).shape)    # (3, 1)

mean = X.mean(axis=0)                        # [3. 1.] — по каждому признаку
std = X.std(axis=0)                          # ≈ [1.633 0.816]
Z = (X - mean) / std                         # broadcasting по строкам
new = np.array([[7, 1]])
print((new - mean) / std)                    # ≈ [[2.449 0.]] — параметры train

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
print(A @ B)                                 # [[19 22] [43 50]]
print(A * B)                                 # [[ 5 12] [21 32]]

batch = np.array([[[1, 0], [3, 2], [5, 4]],
                  [[2, 2], [4, 4], [0, 0]]])
print(batch.shape, batch.mean(axis=1))       # (2, 3, 2) [[3. 2.] [2. 2.]]
```

`X.std` по умолчанию делит на `n`, как и стандартизация в scikit-learn
(`StandardScaler`). Про делитель `n-1` говорилось в уроке о данных: важно
знать, какую величину считает библиотека.

## Типичная ошибка: тихий broadcasting

Broadcasting не только удобен, но и опасен: неверная форма часто не
вызывает ошибки, а молча даёт другой результат.

Допустим, нужно поделить каждое обращение на сумму его строки, чтобы
получить доли признаков. `X / X.sum(axis=1)` падает: формы `(3, 2)` и `(3,)`
сравниваются справа, 2 и 3 не совпадают. С `keepdims=True` сумма имеет
форму `(3, 1)`, и деление работает построчно: первая строка `[3, 2] / 5 =
[0.6, 0.4]`.

Хуже, когда ошибки нет. Вектор формы `(3,)` минус столбец формы `(3, 1)`
даёт не три числа, а таблицу `(3, 3)`: каждый элемент вычитается из каждого.
Программа работает дальше, а метрика получается бессмысленной. Поэтому
после каждой операции с осями полезно напечатать `shape` и сверить его с
тем, что ты ожидаешь по смыслу.

## Проверить понимание

1. Таблица `X` имеет форму `(100, 5)`: 100 обращений, 5 признаков. Какая форма
   у `X.mean(axis=0)` и у `X.mean(axis=1)`, и что означает каждое из этих
   чисел?

<details>
<summary>Разбор вопроса 1</summary>

`X.mean(axis=0)` сворачивает ось обращений: форма `(5,)`, по одному среднему
на признак — именно это нужно для стандартизации. `X.mean(axis=1)`
сворачивает ось признаков: форма `(100,)`, среднее пяти разных признаков у
каждого обращения. Если признаки измеряются в разных единицах, такое число
обычно смысла не имеет.

</details>

2. Можно ли перемножить `(32, 10) @ (10, 3)`? А `(32, 10) @ (3, 10)`?

<details>
<summary>Разбор вопроса 2</summary>

Первое — да: внутренние размеры 10 и 10 совпадают, результат `(32, 3)`.
Второе — нет: слева длина строки 10, справа длина столбца 3. Вероятно,
вторая матрица записана повёрнутой: её транспонирование (строки становятся
столбцами) имеет форму `(10, 3)` и подходит.

</details>

3. После стандартизации по train новое обращение получило значение 4.2 по
   одному признаку. Это ошибка преобразования? Что изменится, если пересчитать
   среднее и отклонение вместе с новыми данными?

<details>
<summary>Разбор вопроса 3</summary>

Не ошибка: 4.2 означает, что значение на 4.2 отклонения больше обучающего
среднего — новые данные выглядят необычно, и это полезный сигнал. Если
пересчитать параметры с учётом новых данных, сигнал спрячется внутри
преобразования, а проверка перестанет быть независимой: мы использовали
информацию, которой при обучении не было.

</details>

4. Почему простое среднее по оси токенов неверно для пачки текстов разной
   длины?

<details>
<summary>Разбор вопроса 4</summary>

Короткие тексты дополнены заполнителями, чтобы все строки пачки имели
одинаковую длину `T`. Простое среднее делит сумму на `T` и учитывает
заполнители как настоящие токены, поэтому у коротких текстов результат
смещается к нулю. Нужно складывать только настоящие токены и делить на их
число.

</details>
