# Как представить задачу числами

Мы хотим оценивать, сколько времени потребуется на обработку обращения. Для
начала будем учитывать только количество необходимых проверок. Позже добавим
другие сведения. На этом примере разберём векторы, матрицы и вычисление
предсказания. Нужны только сложение и умножение: новые обозначения будем
вводить по одному. В конце урока те же операции выберут документ для
ответа на вопрос — как поиск по смыслу в LLM-системах ([зачем это
нужно](00_why_math.md)).

## От наблюдений к формуле

Предположим, по учебным данным одна проверка занимает примерно две минуты, а
ещё минута уходит на открытие обращения. Тогда для трёх проверок получаем `2 ×
3 + 1 = 7` минут.

Запишем ту же мысль короче:

```text
ŷ = w × x + b
```

`x` — количество проверок, наш вход. `w` — сколько минут добавляет каждая
проверка. `b` — время, которое добавляется независимо от числа проверок. `ŷ`
читается «игрек с крышкой» и означает предсказание. Настоящее измеренное время
будем обозначать `y`.

При `w=2`, `b=1`, `x=3` предсказание `ŷ=7`. Если фактически работа заняла 9
минут, модель ошиблась. Пока мы сами выбрали `w` и `b`; в следующем уроке
научим программу подбирать их по примерам. Такую формулу называют **линейной
моделью**.

## Если признаков несколько

Время зависит не только от числа проверок. Допустим, нужно учитывать и число
перезапусков учебного сервиса. Одна проверка добавляет две минуты, перезапуск
— пять, на открытие обращения по-прежнему нужна минута.

Для трёх проверок и двух перезапусков:

```text
2 × 3 + 5 × 2 + 1 = 17 минут
```

Входные сведения, по которым строится предсказание, называют **признаками**.
Запишем их в упорядоченный список `x = [3, 2]`. Такой список чисел —
**вектор**. Весам соответствует вектор `w = [2, 5]`.

Порядок здесь важен. Первая позиция означает число проверок, вторая —
перезапуски. Если поменять входные значения местами, смысл вычисления
изменится.

Умножить соответствующие элементы и сложить результаты — значит вычислить
**скалярное произведение**. Для наших векторов оно равно `3×2 + 2×5 = 16`.
Слово «скаляр» обозначает одно число. Прибавив `b=1`, получаем те же 17 минут.
Обозначение `x·w` — короткая запись этой операции, а `Σ` в формулах означает
«сложить».

## Несколько обращений образуют матрицу

Запишем три обращения строками:

```text
X = [ [3, 2],
      [1, 0],
      [4, 1] ]
```

Получилась таблица из трёх строк и двух столбцов — **матрица** формы `(3, 2)`.
Три строки — три наблюдения, два столбца — два признака. Буквой `X` обозначаем
все входы сразу, а маленькой `x` — вход отдельного примера.

Умножение `X @ w` вычисляет скалярное произведение каждой строки с одним
вектором весов. Результат `[16, 2, 13]`; прибавив единицу к каждому элементу,
получим `[17, 3, 14]`.

```python
import numpy as np

X = np.array([[3, 2], [1, 0], [4, 1]])
w = np.array([2, 5])
predictions = X @ w + 1
print(predictions)  # [17  3 14]
```

NumPy — библиотека операций над массивами чисел. `array` создаёт массив, а `@`
выполняет матричное умножение. Это та же работа, которую мы только что сделали
вручную для каждой строки. Длина вектора весов должна совпадать с числом
признаков.

Позже появятся массивы с большим числом осей, например группа цветных
изображений. Общее название многомерного массива — **тензор**. Сейчас
достаточно уметь назвать, что означает каждая ось конкретных данных;
подробно об осях и формах — в [уроке о массивах](04_arrays_and_axes.md).

## Как сравнить направления векторов

В поиске по тексту пригодится ещё одна операция: сравнение направлений.
Возьмём `a=[3,4]`. Его длина равна `sqrt(3²+4²)=5`; `sqrt` означает квадратный
корень. Для `b=[6,8]` длина 10. Второй вектор вдвое длиннее, но направлен так
же.

Их **косинусное сходство** — скалярное произведение, делённое на произведение
длин:

```text
cosine(a,b) = (3×6 + 4×8) / (5×10) = 50/50 = 1
```

Пара `[1,0]` и `[0,1]` даёт 0, потому что произведение равно нулю. Пара
`[1,0]` и `[-1,0]` даёт -1. Поэтому это показатель направления от -1 до 1, а
не вероятность правильного ответа. Для нулевого вектора длина равна нулю;
деление невозможно, и этот случай нужно обработать явно.

### Мостик к LLM: какой документ вернёт поиск

Языковые модели умеют превращать текст в вектор — **embedding**. Тексты
с похожим смыслом получают векторы с похожим направлением. Как именно
модель этому учится, разберём в разделах 4 и 6; сейчас возьмём готовые
игрушечные векторы из трёх чисел. У настоящих embeddings сотни координат
без названий, а здесь для наглядности считаем, что координаты означают
«вход в аккаунт», «оплата» и «сеть».

```text
запрос «не могу войти»       q  = [2, 1, 0]   длина sqrt(5)  ≈ 2.236
d1 «Как сбросить пароль»     d1 = [3, 1, 0]   длина sqrt(10) ≈ 3.162
d2 «Сеть недоступна»         d2 = [0, 1, 3]   длина sqrt(10) ≈ 3.162
d3 «Длинный FAQ обо всём»    d3 = [4, 4, 4]   длина sqrt(48) ≈ 6.928
```

Сначала скалярные произведения: `q·d1 = 6+1+0 = 7`, `q·d2 = 0+1+0 = 1`,
`q·d3 = 8+4+0 = 12`. Если ранжировать по ним, первым окажется длинный FAQ
— только потому, что его вектор длинный. Теперь косинусы:

```text
cosine(q,d1) = 7  / (2.236 × 3.162) ≈ 0.990
cosine(q,d2) = 1  / (2.236 × 3.162) ≈ 0.141
cosine(q,d3) = 12 / (2.236 × 6.928) ≈ 0.775
```

Поиск по косинусу вернёт «Как сбросить пароль»: его направление почти
совпадает с запросом. Так и работает поиск по смыслу в RAG: вопрос и
фрагменты документов превращают в векторы и берут фрагменты с наибольшим
косинусным сходством.

```python
import numpy as np

query = np.array([2, 1, 0])
docs = np.array([[3, 1, 0],    # «Как сбросить пароль»
                 [0, 1, 3],    # «Сеть недоступна»
                 [4, 4, 4]])   # «Длинный FAQ обо всём»

dot = docs @ query
cosine = dot / (np.linalg.norm(docs, axis=1) * np.linalg.norm(query))
print(dot)                      # [ 7  1 12] — выиграл бы длинный FAQ
print(cosine.round(3))          # [0.99  0.141 0.775]
print(cosine.argmax())          # 0 — поиск вернёт «Как сбросить пароль»
```

`docs @ query` — то же матричное умножение, что и `X @ w` выше: одно
скалярное произведение на документ. `np.linalg.norm(..., axis=1)` считает
длину каждой строки, `argmax` возвращает номер наибольшего элемента.
Высокий косинус означает похожее направление векторов, а не гарантию, что
документ отвечает на вопрос: это нужно проверять отдельно.

## Проверить понимание

1. При признаках `[2,1]`, весах `[2,5]` и свободном члене 1 что предскажет
   модель? Почему нельзя просто добавить третий признак, оставив два веса?
2. Почему два вектора могут указывать в одном направлении, но иметь разную длину
   — и как это влияет на выбор между косинусным сходством и обычным скалярным
   произведением?
3. В примере с поиском вектор FAQ заменили на `[1, 1, 1]` — то же
   направление, длина меньше. Какие числа изменятся и какой документ вернёт
   поиск по косинусу?

<details>
<summary>Разбор вопроса 1</summary>

Ответ: `2×2 + 1×5 + 1 = 10`. Для третьего признака не задан вклад: нужен
третий вес и понимание того, что означает новая координата. Совпадение
размеров отражает согласованность смысла данных и вычисления.

</details>

<details>
<summary>Разбор вопроса 2</summary>

Длина вектора и его направление — независимые свойства: вектор `[2,0]` и
`[10,0]` указывают в одном направлении, но первый в пять раз короче.
Обычное скалярное произведение чувствительно к обеим величинам сразу — оно
вырастет просто от увеличения длины векторов, даже если направление не
изменилось. Косинусное сходство нормирует на длины и измеряет ТОЛЬКО
направление, поэтому им удобно сравнивать смысловую близость представлений
независимо от их масштаба.

</details>

<details>
<summary>Разбор вопроса 3</summary>

Скалярное произведение уменьшится в четыре раза: `2+1+0 = 3` вместо 12,
и FAQ перестанет выигрывать даже по нему. Косинус не изменится:
`3 / (2.236 × 1.732) ≈ 0.775`, как и раньше, потому что направление то
же. Поиск по косинусу по-прежнему вернёт «Как сбросить пароль» (0.990).
Именно поэтому косинусу не важно, насколько «длинным» получился вектор
документа.

</details>
