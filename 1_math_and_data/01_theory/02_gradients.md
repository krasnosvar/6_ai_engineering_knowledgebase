# Как программа подбирает веса: ошибка и градиент

В [предыдущем уроке](01_vectors_and_linear_model.md) мы сами выбрали числа в
формуле `ŷ=w×x+b`. Теперь дадим программе измеренные примеры и научим её
изменять `w` и `b`. К концу урока ты сможешь вручную выполнить один шаг
обучения и объяснить код первой лабы.

## Сначала решим, что считать ошибкой

Возьмём два учебных наблюдения: при одной проверке работа заняла 3 минуты, при
двух — 5 минут. Значит, `x=[1,2]`, `y=[3,5]`. Начнём с `w=0`, `b=0`: модель
предсказывает ноль в обоих случаях.

| Пример | Предсказание | Правильное время | Предсказание минус ответ |
|---|---:|---:|---:|
| x=1 | 0 | 3 | -3 |
| x=2 | 0 | 5 | -5 |

Просто складывать ошибки неудобно: промахи -3 и +3 взаимно уничтожатся, хотя
оба предсказания неверны. Поэтому возведём каждую ошибку в квадрат и усредним:
`((-3)²+(-5)²)/2 = (9+25)/2 = 17`.

Это **средняя квадратичная ошибка**, MSE. Её формула:

```text
L = (1/n) × Σ(ŷ_i - y_i)²
```

`L` — одно число, оценивающее ошибку всей группы; `n` — количество примеров;
индекс `i` означает номер примера. Чем меньше `L`, тем лучше модель описывает
именно эти данные. Функцию, которую уменьшают при обучении, называют
**функцией потерь**, loss.

Квадрат особенно сильно штрафует большие промахи: ошибка 10 даёт 100, ошибка 2
— 4. Другой выбор, MAE, усредняет модули ошибок. Выбор функции зависит от
задачи; сейчас используем MSE, чтобы разобрать обучение.

## В какую сторону менять параметр

Можно немного увеличить `w`, снова посчитать `L` и проверить результат. Но при
миллионах весов перебирать каждое изменение дорого. Нам нужен способ
вычислить, как небольшое изменение каждого веса повлияет на ошибку.

Начнём с обычной функции `f(w)=w²`. При `w=3` она равна 9. При `w=3.01` —
9.0601. На изменение аргумента 0.01 приходится изменение результата 0.0601:
отношение примерно 6. Если делать шаг всё меньше, отношение будет стремиться к
6. Это значение **производной** функции в точке 3. Для квадрата производная
равна `2w`.

Производная показывает локальный темп изменения. Положительное значение
говорит: небольшое увеличение параметра увеличивает функцию. Чтобы уменьшить
её, следует двигаться в обратную сторону. Для многих параметров набор таких
производных называется **градиентом**.

## Вычислим градиент нашей ошибки

Обозначим ошибку одного примера через `e_i=w×x_i+b-y_i`. Производная квадрата
`e_i²` по самой ошибке равна `2e_i`. При изменении `w` ошибка меняется с
коэффициентом `x_i`; при изменении `b` — с коэффициентом 1. Поэтому вклады
одного примера равны `2e_i×x_i` и `2e_i`. Это применение цепного правила:
учитываем последовательно влияние одного вычисления на другое.

Усредним вклады всех примеров:

```text
dL/dw = (2/n) × Σ(e_i × x_i)
dL/db = (2/n) × Σ e_i
```

Запись `dL/dw` читается «производная ошибки по весу w». При наших начальных
весах ошибки -3 и -5. Получаем:

```text
dL/dw = (2/2) × (-3×1 + -5×2) = -13
dL/db = (2/2) × (-3 + -5) = -8
```

Оба значения отрицательные: небольшое увеличение обоих параметров должно
уменьшить ошибку.

## Сделаем один шаг

Не будем прибавлять сразу 13 и 8: локальное направление не гарантирует удачный
большой скачок. Возьмём десятую часть изменения. Коэффициент 0.1 называется
**скоростью обучения**, learning rate. Шаг против градиента:

```text
w_new = w - 0.1 × dL/dw = 0 - 0.1×(-13) = 1.3
b_new = b - 0.1 × dL/db = 0 - 0.1×(-8) = 0.8
```

Новые предсказания: `1.3×1+0.8=2.1` и `1.3×2+0.8=3.4`. Новая MSE:
`((2.1-3)²+(3.4-5)²)/2 = (0.81+2.56)/2 = 1.685`. Ошибка уменьшилась с 17 до
1.685. Именно это произошло за один шаг обучения.

Далее заново вычисляем ошибки и градиент уже для новых параметров. Такой
процесс называется **градиентным спуском**. При слишком большом learning rate
можно перескакивать область малого loss и расходиться; при слишком маленьком
обучение идёт медленно.

## Как проверить собственную формулу

Возьми маленькое число `ε=0.00001` и посчитай:

```text
численная производная ≈ (L(w+ε,b) - L(w-ε,b)) / (2ε)
```

Мы измеряем изменение ошибки по обе стороны от текущего веса. Для простого
численного примера результат должен быть близок к выведенной производной.
Слишком маленькое ε неудобно из-за ограниченной точности хранения чисел в
компьютере.

скомпенсировать друг друга, и дополнительно сильнее штрафует именно большие
промахи.
