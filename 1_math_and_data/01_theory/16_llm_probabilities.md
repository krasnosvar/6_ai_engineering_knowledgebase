# Вероятности токенов, temperature и perplexity

В [предыдущем уроке](15_classification_probabilities.md) softmax
превратил оценки классов в доли. Языковая модель применяет похожий
расчёт к возможным продолжениям текста. Рассмотрим маленький пример;
настоящий словарь и контекст значительно больше.

## Мостик к LLM: logprobs, temperature и perplexity

Языковая модель на каждом шаге выдаёт по оценке на каждый токен
словаря: какой кусочек текста может идти следующим. Эти сырые оценки
называют **logits**. Softmax превращает их в вероятности точно так же,
как оценки команд в прошлом уроке.

Пусть после «Сбросьте ваш» у трёх токенов logits `[2, 1, 0]`: «пароль»,
«логин», «аккаунт». Числа те же, что у трёх команд, поэтому и
вероятности те же: `0.665`, `0.245`, `0.090`.

Многие API по запросу возвращают **logprobs** — натуральные логарифмы
вероятностей токенов. Для «пароль» это `ln(0.665) ≈ -0.408`. Это и есть
«странные отрицательные числа» в логах: чем ближе к нулю, тем увереннее
модель. Логарифмы удобно складывать по длинной фразе: так мы избегаем
перемножения очень маленьких чисел, как в уроке об экспоненте.

**Temperature** `T` делит logits перед softmax. Посчитаем:

| T | logits / T | Вероятности «пароль», «логин», «аккаунт» |
|---|---|---|
| 0.5 | `[4, 2, 0]` | `[0.867, 0.117, 0.016]` |
| 1 | `[2, 1, 0]` | `[0.665, 0.245, 0.090]` |
| 2 | `[1, 0.5, 0]` | `[0.506, 0.307, 0.186]` |

Для `T = 0.5`: `e⁴ ≈ 54.60`, `e² ≈ 7.389`, `e⁰ = 1`, сумма `62.99`, доля
лидера `54.60/62.99 ≈ 0.867`. Маленькая температура усиливает различия
между logits: при случайной выборке токен «пароль» выпадает чаще.
Большая сглаживает их, и другие токены получают больше шансов. При
выборе самого вероятного токена порядок не меняется и температура сама
по себе не меняет выбор. Подробнее — в [разделе 4, жизненный
цикл модели](../../4_nlp_and_transformers/01_theory/05_model_lifecycle.md).

Теперь потеря. Пусть на фразе из трёх токенов модель дала правильным
токенам вероятности `0.5`, `0.25` и `0.8`. Потеря каждого токена —
знакомая `-ln(p)`: `0.693`, `1.386`, `0.223`. Их сумма равна
`-ln(0.5 × 0.25 × 0.8) = -ln(0.1) ≈ 2.303` — логарифм превратил
произведение в сумму. Средняя потеря на токен `2.303 / 3 ≈ 0.768`.

**Perplexity** — экспонента средней потери: `exp(0.768) ≈ 2.15`. Это
эквивалентный средний уровень неопределённости, как если бы правильный
токен на каждой позиции получал вероятность `1 / 2.15`. На отдельных
позициях вероятности различаются. Эту метрику считают при обучении
языковых моделей — [раздел 4, обучение
LM](../../4_nlp_and_transformers/01_theory/04_architectures_and_lm_training.md).

```python
import numpy as np

logits = np.array([2.0, 1.0, 0.0])
for t in (0.5, 1, 2):
    e = np.exp(logits / t)
    print(t, (e / e.sum()).round(3))
# 0.5 [0.867 0.117 0.016]
# 1 [0.665 0.245 0.09 ]
# 2 [0.506 0.307 0.186]

p = np.array([0.5, 0.25, 0.8])     # вероятности правильных токенов
print(np.log(p).round(3))          # [-0.693 -1.386 -0.223] — logprobs
loss = -np.log(p)
print(loss.mean().round(3))        # 0.768 — средняя потеря на токен
print(np.exp(loss.mean()).round(2))  # 2.15 — perplexity
```

## Ограничения вычислений

При больших оценках экспонента может переполниться. Устойчивый softmax вычитает
максимум до вычисления экспонент; подробнее это разобрано в [уроке о
нейронах](../../3_neural_networks/01_theory/01_neurons_and_backprop.md). Если
вероятность правильного токена равна нулю, её логарифмическая потеря бесконечна.
На практике важно учитывать численную точность.

## Проверить понимание

1. API вернул для двух токенов logprobs `-0.1` и `-2.3`. Какой токен
   модель считала более вероятным и примерно с какой вероятностью?
2. На фразе из трёх токенов модель дала каждому правильному токену
   вероятность 0.5. Чему равны средняя потеря и perplexity и как их
   истолковать?

<details>
<summary>Разбор вопроса 1</summary>

Logprob — это `ln(p)`, поэтому вероятность возвращается экспонентой:
`exp(-0.1) ≈ 0.905`, `exp(-2.3) ≈ 0.100`. Увереннее модель в первом
токене: его logprob ближе к нулю. Logprob 0 означал бы вероятность 1.

</details>

<details>
<summary>Разбор вопроса 2</summary>

Потеря каждого токена `-ln(0.5) ≈ 0.693`, средняя тоже 0.693.
Perplexity `exp(0.693) = 2`: модель на каждом шаге колеблется как при
выборе из двух равновероятных вариантов. Если бы все вероятности были 1,
потеря была бы 0, а perplexity — 1: никаких колебаний.

</details>
