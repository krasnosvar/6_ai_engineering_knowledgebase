# Рамки и точность документов

Две функции, письменный вопрос и необязательный CV-эксперимент. Код
пиши в [task.py](task.py): там есть заготовки `iou` и
`document_accuracy`, каждая пока поднимает `NotImplementedError`.
Профиль **CPU**; ориентир — 2–3 часа.

## Как проверять

Из корня репозитория:

```bash
uv run python 11_multimodal_and_cv/03_exercises/check.py
```

`check.py` проверяет сначала `iou`, затем `document_accuracy`. Пока
функция не написана, проверка останавливается на её
`NotImplementedError` — это ожидаемо. `AssertionError` без текста значит,
что функция вернула не то значение; `AssertionError: Expected
ValueError` — что на неверный вход функция не подняла `ValueError`. Когда
обе готовы, печатается `PASS: 11_multimodal_and_cv student`.

## 1. Пересечение рамок — `iou(a, b)`

Урок: [Чем распознавание цифры отличается от разбора
документа](../01_theory/02_next_steps.md), раздел про IoU.

Дано: две рамки — кортежи `(x1, y1, x2, y2)`, левый верхний и правый
нижний углы. Сделать: вернуть площадь пересечения, делённую на площадь
объединения. Совпадающие рамки дают 1, непересекающиеся — 0; квадраты
`(0,0,2,2)` и `(1,1,3,3)` — `1/7`, как в уроке.

`ValueError`: в рамке не 4 числа; координата NaN или бесконечность;
`x2 ≤ x1` или `y2 ≤ y1` (рамка нулевой или отрицательной ширины).

Подсказка: перекрытие по одной оси — «меньший правый край минус больший
левый»; если получилось отрицательное число, рамки по этой оси не
пересекаются.

## 2. Полностью верные документы — `document_accuracy(truth, pred, fields)`

Урок тот же, раздел «Почему точность полей и документов различается».

Дано: `truth` и `pred` — словари `doc_id → словарь полей`, `fields` —
список обязательных полей. Сделать: вернуть долю документов из `truth`,
у которых в `pred` есть все поля из `fields` и каждое совпадает с
эталоном.

Правила: отсутствующий в `pred` документ — ошибка; отсутствующее поле —
ошибка, даже если в эталоне там `None` (пропуск и явный null — разные
ответы); лишние документы в `pred` здесь не учитываются.

`ValueError`: пустой `truth` или пустой `fields` — доля от нуля
документов или по нулю полей не имеет смысла.

## 3. Чего не видит эта метрика (письменно)

Объясни, почему кроме `document_accuracy` нужно отдельно оценить ложные
документы (найденные там, где их нет) и ошибки OCR, и что произойдёт,
если считать только поля.
