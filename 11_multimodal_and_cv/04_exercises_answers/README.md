# Разбор: рамки и точность документов

Открывай после своей попытки. Код — в [solution.py](solution.py).

## 1. `iou`

Ход мысли: сначала проверить обе рамки, потом считать. Перекрытие по x —
`min(правые края) − max(левых краёв)`, по y — так же. Если рамки не
пересекаются по оси, разность отрицательна, и её обрезают до нуля через
`max(0, ...)`. Площадь пересечения — произведение перекрытий. Объединение
— сумма площадей минус пересечение: иначе общая часть посчитана дважды.

Проверим на квадратах урока: перекрытие по x `min(2,3) − max(0,1) = 1`,
по y тоже 1, пересечение 1; объединение `4 + 4 − 1 = 7`; IoU `1/7`.

Типичные ошибки:

- не обрезать перекрытие нулём: две отрицательные разности дадут
  положительное «пересечение» у далёких рамок;
- делить на сумму площадей без вычитания пересечения;
- пропустить проверку `x2 > x1`: рамка нулевой ширины даст деление на
  ноль, если вторая тоже вырождена.

IoU не сравнивает классы объектов, поэтому само по себе не является
полной метрикой detection: нужно ещё сопоставить предсказания с
объектами и учесть пропуски и ложные находки.

## 2. `document_accuracy`

Ход мысли: идём по документам эталона, а не предсказания, — знаменатель
`len(truth)`. Документ засчитывается, только если в предсказании он есть
и все обязательные поля присутствуют и совпадают; на первом несовпадении
можно прекратить проверку документа (`break`).

Тонкость с `None`: проверка `predicted_row.get(k) == true_row[k]` для
эталона `{'x': None}` и пустого предсказания `{}` даст `None == None` —
верно, и пропуск засчитается как правильный ответ. Поэтому решение
отдельно проверяет `k in predicted_row`. Это и проверяет второй `assert`
для `document_accuracy` в `check.py`.

Типичные ошибки: считать по документам `pred` (лишние документы сдвинут
знаменатель), использовать `.get` без проверки наличия поля, вернуть 0
для пустого `truth` вместо `ValueError` — тогда «нет данных» не
отличается от «всё неверно».

## 3. Ложные документы и ошибки OCR

`document_accuracy` смотрит только на документы из эталона. Если система
нашла три лишних «счёта» на рекламной странице, метрика этого не увидит,
а следующий процесс получит три ложные оплаты. Поэтому ложные находки
считают отдельно (по аналогии с precision). Ошибки OCR полезно измерять
до извлечения полей: тогда видно, где теряется качество — при чтении
текста или при выборе поля.
