# Примеры и эксперименты

Команды выполняются из корня репозитория после установки зависимостей.
Оба примера — профиль **CPU**: веса и сеть не нужны. Для каждого опыта
сначала запиши предсказание, затем измени одно условие и сравни.

## 01_digits.py — маленькая CNN на цифрах

После урока [Как нейросеть работает с
изображением](../01_theory/01_convolutions_basics.md).

```bash
uv run python 11_multimodal_and_cv/02_examples/01_digits.py
```

Входные данные — встроенный в scikit-learn набор digits: 1797
чёрно-белых изображений цифр 8×8 с яркостью от 0 до 16. Скачивать ничего
не нужно. Скрипт делит их на train и test (75% и 25%, с сохранением
долей классов), делит яркость на 16 и добавляет ось каналов:
`(N,8,8) → (N,1,8,8)`.

Сеть — ровно та, что разобрана в уроке: `Conv2d(1,8,3,padding=1)` →
`ReLU` → `Flatten` → `Linear(512,10)`. Комментарий над моделью повторяет
таблицу форм из урока; в скрипте batch равен 64, а не 32, поэтому первая
ось другая. Цикл обучения — тот же, что в разделе 3: 8 эпох, Adam,
cross entropy.

Как читать вывод. Одна строка `held-out digits accuracy: ...` — доля
верно определённых цифр на test. В нашем запуске было 0.9644; на другой
версии PyTorch число может немного отличаться, хотя seed фиксирован.
`assert` проверяет только, что accuracy выше 0.85.

Что доказывает: свёрточная сеть обучается на изображениях тем же циклом,
что и полносвязная, и формы из урока сходятся. Чего не доказывает:
качество на фотографиях документов (другие фон, освещение, разрешение) и
превосходство CNN — один split на маленьком наборе.

Одно изменение. Поменяй `padding=1` на `padding=0` и сначала запусти, не
трогая `Linear`. Предскажи по формуле урока размер карты и текст ошибки.
Ожидаемо: карта 6×6, после Flatten 288 чисел, ошибка `mat1 and mat2
shapes cannot be multiplied (64x288 and 512x10)`. Исправь `8 * 8 * 8` на
`8 * 6 * 6` и запусти снова: скрипт должен отработать.

Второй опыт (необязательный, он же CV-расширение упражнений): замени
модель на линейный классификатор того же входа —
`nn.Sequential(nn.Flatten(), nn.Linear(64, 10))` — и сравни accuracy на
том же split. В нашем запуске линейная модель дала 0.9333, CNN — 0.9644.
Разница в 3 пункта на 450 тестовых изображениях невелика; перед выводом
«CNN лучше» повтори с другим `random_state`.

## 02_document_fields.py — точность полей и документов

После урока [Чем распознавание цифры отличается от разбора
документа](../01_theory/02_next_steps.md).

```bash
uv run python 11_multimodal_and_cv/02_examples/02_document_fields.py
```

Входные данные — учебные фикстуры в коде: эталон `truth` и предсказание
`pred` для трёх документов с полями `date` и `amount`. Это симуляция
результата извлечения: OCR и VLM здесь не запускаются. Ошибки взяты из
урока: во втором документе перепутаны день и месяц, в третьем потерян
ноль в сумме. Списки заранее выровнены по порядку: `zip` не сопоставляет
ID и при перестановке строк сравнит разные документы.

Как читать вывод. `field accuracy: 0.666...` — 4 верных поля из 6;
`fully correct documents: 0.333...` — 1 полностью верный документ из 3.
Числа совпадают с ручным расчётом урока.

Что доказывает: доля верных полей переоценивает пригодность, когда
следующему процессу нужен целиком верный документ. Чего не доказывает:
качество какого-либо реального OCR; не учитываются пропущенные и лишние
документы.

Одно изменение. Удали поле `amount` из первого предсказания. Предскажи
обе метрики. Ожидаемо: 3/6 = 0.5 и 0/3 = 0.0 — `p.get(k)` вернёт `None`,
и пропуск засчитается ошибкой. Затем добавь в конец `pred` четвёртый документ
`id: 'd'`, которого нет в эталоне, и подумай: изменятся ли метрики? Нет —
`zip` его просто не увидит; ложные документы нужно считать отдельно.
