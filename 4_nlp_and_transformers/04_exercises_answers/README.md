# Разбор: Устойчивая нормализация и причинная маска

## Задание 1. softmax

Ход мысли. Формула `exp(v) / сумма exp` верна, но `math.exp(1000)` не
помещается в float. Вычтем из всех чисел максимум `top`: каждая экспонента
умножится на одно и то же `exp(-top)`, и в дроби этот множитель сократится,
поэтому доли не изменятся. Зато наибольшее число станет 0, а `exp(0)=1` —
переполнения нет. Для `[1000, 1000]`: сдвиг даёт `[0, 0]`, экспоненты
`[1, 1]`, сумма 2, ответ `[0.5, 0.5]`.

Проверку входа делаем до расчёта: пустой список дал бы деление на ноль, а
`inf` или `nan` — бессмысленные доли. `math.isfinite(v)` ложно для всех
трёх случаев `inf`, `-inf`, `nan`.

Типичные ошибки:

- вычесть минимум вместо максимума — для `[-1000, 0, 1000]` получится
  `exp(2000)`, и переполнение вернётся;
- поймать `OverflowError` и вернуть что-то «примерное» вместо устойчивой
  формулы;
- забыть, что `-inf` тоже недопустим: проверка только на `inf` его
  пропустит.

## Задание 2. causal_allowed

Ход мысли. Строка i — текущая позиция, столбец j — позиция, на которую она
смотрит. Разрешено `j <= i`, поэтому значение ячейки — просто результат
сравнения `j <= i`. Два вложенных цикла строят таблицу строка за строкой.

Длину проверяем через `type(length) is not int`, а не
`isinstance(length, int)`: в Python `bool` — подкласс `int`, и
`isinstance(True, int)` равно `True`. Без этой проверки `causal_allowed(True)`
молча вернул бы маску длины 1.

Типичная ошибка — перепутать направление и разрешить `j >= i`: получится
маска «только будущее», и проверка `check.py` на `length=3` это покажет.

## Задание 3. Эксперимент

Число голов должно делить `d_model`: при 32 подходят 1, 2, 4, 8, 16, 32.
Изменение архитектуры меняет сам эксперимент даже при том же числе шагов,
поэтому сравнивай loss только при прочих равных. Без маски позиция может
взять целевой токен прямо из входа: низкий train loss тогда показывает
умение копировать, а при генерации будущего нет и копировать нечего.
