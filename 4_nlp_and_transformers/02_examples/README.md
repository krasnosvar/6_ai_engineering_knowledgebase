# Примеры и эксперименты

Команды выполняются из корня репозитория после установки зависимостей. Все
три примера раздела — профиль **CPU**: им не нужны готовые веса, сеть и
внешние данные. Каждый пример — расчёт на маленьких числах, а не измерение
качества настоящей модели. Перед изменением кода сначала запиши своё
предсказание, затем меняй одно условие и сравнивай.

## 01_bpe.py

**После урока:** [как текст превращается во
вход](../01_theory/01_tokenization.md).

**Идея.** Словарь частей слов строится из частот соседних пар, а новое слово
собирается из выученных частей.

**Входные данные.** Тот же корпус, что в ручном разборе урока: `low` ×5,
`lower` ×2, `newest` ×6, `widest` ×3. Код делает 8 объединений; при равной
частоте выбирает пару, первую по алфавиту, как в уроке.

```bash
uv run python 4_nlp_and_transformers/02_examples/01_bpe.py
```

**Как читать вывод.** Строка `merges:` — объединения по порядку. Первые три,
`('e','s')`, `('es','t')`, `('est','</w>')`, совпадают с шагами 1–3 урока,
следующие два, `('l','o')` и `('lo','w')`, — с продолжением разбора. Строка
`lowest => ('low', 'est</w>')` показывает разбиение слова, которого не было
в корпусе. `assert` внутри цикла проверяет, что склейка частей
восстанавливает исходное слово.

**Что доказывает и чего нет.** Показывает механику обучения BPE и его
зависимость от частот корпуса. Не показывает, как режет текст настоящий
токенизатор модели: у промышленных есть байты, нормализация и специальные
токены.

**Изменение.** В словаре `words` в начале файла поставь `'lower': 50`.
Предскажи заранее, какая пара станет первой (посчитай `l o`, `o w`, `w e`,
`e r` с новой частотой). Если первая строка `merges:` совпала с твоим
расчётом — ты понял, откуда берутся объединения.

## 02_attention.py

**После урока:** [как Transformer учитывает соседние
слова](../01_theory/02_attention.md).

**Идея.** Causal mask: каждая позиция смешивает только себя и прошлое, а
изменение последнего токена не меняет выходы ранних позиций.

**Входные данные.** Три позиции по два числа: `[1,0]`, `[0,1]`, `[1,1]`.
В отличие от урока, проекции не обучаются и не подобраны: `Q=K=V=x`. Так в
коде остаются только оценки, маска и softmax — то, что проверяется.

```bash
uv run python 4_nlp_and_transformers/02_examples/02_attention.py
```

**Как читать вывод.** `weights` — матрица `(3,3)`: строка i — доли, с
которыми позиция i берёт values. Выше диагонали нули — это маска. Строка 2:
оценки `[0, 1/1.414]`, после softmax примерно `[0.33,0.67]`. Строка
`Future-token invariance: PASS` значит, что все три проверки прошли: суммы
строк равны 1, будущие веса нулевые, а замена последнего вектора на
`[100,-100]` не изменила выходы позиций 1 и 2.

**Что доказывает и чего нет.** Доказывает свойства маски на этих числах.
Ничего не говорит о качестве attention с обученными весами.

**Изменение.** Закомментируй строку с `np.triu_indices` (установку `-inf`).
Предскажи, какая из трёх проверок упадёт первой. Ожидаемый результат —
`AssertionError` на проверке нулевых весов будущего: так видно, что
проверка действительно ловит отсутствие маски.

## 03_tiny_transformer.py

**После уроков:** [блок Transformer](../01_theory/03_transformer_block.md) и
[обучение языковой
модели](../01_theory/04_architectures_and_lm_training.md).

**Идея.** Маленькая decoder-only модель учится предсказывать следующий
символ: вход и цели сдвинуты на одну позицию, causal mask запрещает
подсматривать.

**Входные данные.** Одна строка из трёх коротких фраз, повторённая 40 раз;
токен — один символ (словарь из 20 символов). 100 шагов обучения, batch из
8 кусков длиной 24.

```bash
uv run python 4_nlp_and_transformers/02_examples/03_tiny_transformer.py
```

**Как читать вывод.** Первая строка — loss в начале и в конце обучения. В
начале он около `ln(20)≈3.0`: случайная модель даёт каждому из 20 символов
примерно равную вероятность. У нас при фиксированном seed было
`loss 3.195 -> 0.246`; на другой версии PyTorch или другом процессоре числа
могут немного отличаться. Вторая строка — greedy-генерация от `metrics `.
Начало похоже на обучающий текст, затем модель сбивается в бессмыслицу вроде
`rstarin rerrics s s st`. Это нормально: сеть крошечная и выучила лишь
частые куски одной строки. Не ожидай связного текста.

**Что доказывает и чего нет.** Доказывает, что связка embedding → блок →
logits → cross entropy обучается, а маска работает (проверка `assert` на
изменённом последнем символе). Не доказывает обобщение: loss считается на
том же тексте, на котором шло обучение, — это запоминание.

**Изменение.** В `nn.TransformerEncoderLayer(32, 4, 64, ...)` замени число
голов 4 на 8, затем на 5. Предскажи: при 8 длина головы `32/8=4`, сеть
обучится; при 5 создание слоя упадёт ещё до обучения, потому что 32 не
делится на 5 (`AssertionError: embed_dim must be divisible by num_heads`).
Второй опыт: в цикле обучения замени `range(100)` на `range(20)`. Предскажи,
что конечный loss будет заметно выше, а генерация — ещё хуже. Конкретные
числа зависят от версии PyTorch; важно направление изменения.
