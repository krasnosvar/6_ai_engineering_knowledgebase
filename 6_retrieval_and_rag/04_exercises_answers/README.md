# Разбор: авторизация, объединение рангов и ANN

[Код решения](solution.py) с комментариями. Проверка эталона из корня:

```bash
uv run python 6_retrieval_and_rag/03_exercises/check.py --answers
```

Проверки подтверждают контракт функций на обычных и граничных случаях. Для
освоения темы нужен и твой письменный вывод из задания 3.

## 1. `authorized_topk`

Ход мысли: права — это фильтр множества кандидатов, а не поправка к
результату. Поэтому порядок такой: отфильтровать, отсортировать, взять k.
В проверке чужой документ `private` имеет score 10 — больше всех. Если
сначала взять top-1, а потом отфильтровать, ответ команды `a` будет пустым,
хотя её документ `own` существует.

Типичные ошибки: сортировать по возрастанию (забыть минус в ключе);
не задать второй ключ `id`, и тогда порядок при равных score зависит от
порядка входа; принять `k=True` как 1.

## 2. `rrf`

Ход мысли: сырые оценки разных методов имеют разные шкалы, а места —
одну. Каждый рейтинг добавляет документу `1/(k+rank)`; документ из
нескольких списков получает несколько вкладов. Для `[['a','b'],
['b','c']]`: `a = 1/61`, `b = 1/62 + 1/61`, `c = 1/62`, поэтому b первый.

Типичные ошибки: нумеровать rank с нуля (вклад первого места станет
`1/60`); перепутать константу k с числом результатов Recall@k; молча
принять повтор ID в одном рейтинге — это ошибка в данных, иначе документ
получит двойной вклад.

## 3. Recall на dev

На четырёх dev-вопросах (q1–q4) нужный документ у всех стоит первым,
поэтому Recall@1 = Recall@3 = 1.0. Вопросов без ответа в dev нет: q8
относится к test, его учитывают отдельно (ожидаемый результат — пустая
выдача или отказ). Такой результат — проверка механики на игрушечных
вопросах, а не доказательство качества поиска.

Фильтрация после top-k: пусть для команды A три лучших по score документа
принадлежат команде B, а документ A стоит четвёртым. Top-3 → фильтр →
пустой список, хотя допустимый источник был. Фильтр до top-k вернул бы его.

## 4. `ann_recall_at_k`

Ход мысли: сравниваем ANN с точным перебором, а не с разметкой — так
видно, сколько соседей потерял сам индекс. Берём множества первых k ID
обоих списков и считаем пересечение. Если ANN вернул меньше k ID,
недостающие считаются промахами, поэтому делим на k, а не на длину ответа
ANN: `ann_recall_at_k(['d1'], exact, 2) = 1/2`, а не 1.

Типичные ошибки: делить на `len(approx_ids)`; сравнивать позиции, а не
множества (порядок внутри top-k не важен); не проверить, что в
`exact_ids` хватает k элементов.

## 5. `ivf_candidates`

Ход мысли: это первый шаг `ivf_topk` из урока — сходство запроса с
центрами, n_probe ближайших ячеек, все их документы. Для запроса
`[0.9, 0.1]` и центров `[1,0], [0,1], [-1,0]` сходства `0.9, 0.1, -0.9`;
при `n_probe=1` берём ячейку 0, а в ней документы 0 и 3. Устойчивая
сортировка (`kind='stable'`) при равных сходствах оставляет меньший номер
первым, поэтому результат не зависит от случая. Дальше среди кандидатов
считают сходства и берут top-k; больше n_probe — больше кандидатов, выше
recall и больше работы.

Типичные ошибки: сортировать сходства по возрастанию и брать дальние
ячейки; вернуть номера ячеек вместо номеров документов; не проверить, что
номера в `cell` существуют, — тогда документ «несуществующей» ячейки
никогда не найдётся, и ошибка останется незамеченной.
