# Память и хвост задержек

1. Реализуй `kv_bytes(layers,batch,tokens,kv_heads,head_dim,bytes_per_value)`.
   Все аргументы — положительные целые. Это оценка только KV cache.
2. Реализуй `nearest_rank(values,p)` для 0<p<=1: отсортируй значения и верни
   элемент с индексом `ceil(p*n)-1`. Поднимай `ValueError`, если список пуст
   или в нём есть недопустимая задержка: NaN, бесконечность или
   отрицательное число. Не меняй входной список.
3. Для `[1,1,1,1,20]` сравни среднее и p95; объясни, почему 5 измерений мало.
4. Реализуй `span_tree_summary(spans)` для trace из [урока о
   наблюдаемости](../01_theory/04_llm_observability.md). `spans` — список
   кортежей `(id, parent, start, end)`: `parent` — id родителя или `None`
   у корня, время — целые миллисекунды. Верни словарь `{id: (total,
   self)}`: `total = end − start`, `self` — `total` минус сумма `total`
   прямых детей, то есть время, которое не объясняют дочерние spans.
   `ValueError`: не кортеж из 4 полей, повтор id, нецелое время, `start <
   0` или `end < start`, неизвестный родитель или span сам себе родитель,
   ребёнок выходит за интервал родителя, отрицательный `self` (в этом
   задании дети одного родителя не пересекаются).
5. Реализуй `redact(text)`: замени ключи вида `sk-...` (после `sk-` буквы,
   цифры, `_` или `-`, перед `sk` — граница слова) на `sk-***`, а адреса
   почты — на `<email>`. Не строка — `ValueError`. `task-42` и одиночное
   `sk-` ключами не считаются. Приведи пример персональных данных,
   которые твоё выражение пропустит.

CPU; 2–3 часа. В отчёте отдельно укажи, что в формуле памяти отсутствует.
