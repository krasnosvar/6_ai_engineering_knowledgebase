# Разбор: память, хвост задержек и trace

Открывай после своей попытки. Код всех функций — в [solution.py](solution.py).

## 1. `kv_bytes`

Ход мысли: для каждой сохранённой позиции, в каждом слое, в каждой
последовательности batch и в каждой KV-голове хранятся два вектора длины
`head_dim` — key и value. Поэтому все шесть размеров перемножаются, а
результат удваивается. `math.prod` перемножает элементы кортежа.

Типичные ошибки:

- подставить число query-голов вместо KV-голов: при GQA их меньше, и
  оценка выйдет завышенной;
- забыть двойку и посчитать только keys;
- проверять аргументы через `v <= 0` и пропустить `1.5` или `True`;
  решение требует `type(v) is int`.

В оценку не входят веса, временные буферы (активации) и память среды
исполнения — самой библиотеки PyTorch и её служебных структур.

## 2. `nearest_rank`

Ход мысли: номер элемента считают с 1, `ceil` округляет вверх, а индекс
в Python — с 0, отсюда `ordered[rank - 1]`. `sorted` возвращает новый
список, поэтому вход не меняется; `values.sort()` изменил бы список
вызывающего кода — это и ловит `check.py`.

Типичные ошибки: `int(p * n)` вместо `ceil` (округление вниз даёт другой
элемент), индекс `rank` без `- 1`, проверка значений после сортировки
(NaN ломает сортировку молча).

## 3. Среднее против p95

Среднее `(1+1+1+1+20)/5 = 4.8` с. p95: `ceil(0.95·5) = 5`, пятый элемент
отсортированного списка — 20 с. Среднее говорит «обычно около пяти
секунд», хотя четыре пользователя из пяти ждали секунду, а один —
двадцать. p95 показывает хвост. Но при пяти значениях p95 просто равен
максимуму: одно случайное медленное измерение целиком определяет оценку,
и следующий прогон может дать совсем другое число.

## 4. `span_tree_summary`

Ход мысли: два прохода. Первый собирает словарь по id и проверяет
каждый span отдельно: формат, повтор, целые времена, порядок начала и
конца. Второй, когда известны все id, для каждого ребёнка находит
родителя, проверяет вложенность интервалов и прибавляет длительность
ребёнка к сумме родителя. Второй проход нужен, потому что ребёнок может
стоять в списке раньше родителя. Собственное время — разница полного и
суммы детей.

Для trace из урока у `request` и `retrieve` собственное время 0: дети
объясняют всё, а почти всё время — в `llm.generate` (2780 мс). В
вопросе 1 урока `self` у `request` равен 1800 мс: это время вне
записанных шагов, куда стоит добавить spans.

Отрицательный `self` означает нарушение условия о непересекающихся
детях. При этом некоторые пересечения дают и неотрицательную разницу,
поэтому одна эта проверка не обнаруживает их все. Для параллельных детей
собственное время считают по объединению интервалов; здесь их отсутствие
задано условием.

Типичные ошибки: один проход по списку (падает, если ребёнок раньше
родителя), вычитание длительности внуков из родителя (вычитать нужно
только прямых детей — внуки уже внутри детей), `isinstance(start, int)`
вместо `type(start) is int` (пропустит `True`).

## 5. `redact`

Ход мысли: два регулярных выражения. `\b` перед `sk-` требует границы
слова, поэтому `task-42` не портится. `+` требует хотя бы одного символа
ключа, и одиночное `sk-` остаётся. Ключ заменяют первым, почту — вторым.

Выражение для почты ловит распространённые адреса, но не все допустимые
по стандарту. Имя, телефон, номер договора или диагноз в свободном
тексте оно пропустит. Поэтому маскирование дополняют ограничением того,
что вообще пишется в trace, правами на просмотр и сроком хранения.

Типичная ошибка — шаблон `sk-\w*`: `*` разрешает ноль символов, и
одиночное `sk-` станет `sk-***`; без `\b` пострадает `task-42`.
