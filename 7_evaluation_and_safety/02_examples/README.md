# Примеры и эксперименты

Команды выполняются из корня репы после установки зависимостей. Все три
примера раздела — профиль **CPU**: им не нужны веса моделей и сеть. Это
расчёты на заранее записанных данных, а не измерение настоящей системы.
Для каждого опыта сначала предскажи результат, затем измени одно условие.

## 02_access.py — права доступа не зависят от текста

После [урока 1](../01_theory/01_free_text_evaluation.md) (раздел «Проверим
границы доверия»).

```bash
uv run python 7_evaluation_and_safety/02_examples/02_access.py
```

Что делает. Функция `authorize` оставляет документы `public` и команды
пользователя из учебного корпуса `data/documents.json` (тот же, что в
разделе 6). Команда приходит параметром из «проверенной авторизации», а
строка с попыткой injection (`malicious`) только печатается: у неё нет
пути в `authorize`. Два `assert` проверяют, что d9 (бюджет atlas команды
A) доступен, а d10 (команды B) — нет.

Как читать вывод. `Authorized IDs` — все ID, кроме d10. `PASS` значит,
что оба `assert` прошли; если бы d10 попал в список, программа упала бы с
`AssertionError`.

Что доказывает и чего нет. Пример проверяет инвариант «документ команды B
не попадает пользователю A» для этого кода. Он не ловит injection и не
доказывает безопасность всей системы — это разобрано в [уроке
5](../01_theory/05_guardrails_and_injection.md).

Одно изменение. Замени `'team-a'` в вызове `authorize` на `'team-b'`.
Предскажи, какой `assert` упадёт первым. Ответ: `assert 'd9' in
visible_ids` — у команды B нет доступа к d9. Падение здесь правильное:
`assert` записаны для команды A. Перепиши их для B (d10 есть, d9 нет) —
так получается отрицательная проверка для второй команды.

## 01_bootstrap.py — парный интервал для разности версий

После [урока 2](../01_theory/02_comparing_versions.md).

```bash
uv run python 7_evaluation_and_safety/02_examples/01_bootstrap.py
```

Что делает. Две версии ответили на одни и те же 10 вопросов (1 — верно,
0 — неверно). Функция `paired_interval` 3000 раз выбирает номера вопросов
с возвращением, одинаковые для обеих версий, и считает разность средних.
Границы интервала — элементы с индексами 75 и 2925 отсортированного
списка разностей. В уроке тот же шаг разобран вручную на пяти вопросах;
здесь вопросов 10, чтобы интервал был чуть уже.

Как читать вывод.

```text
delta=0.100; approximate 95% interval=[-0.200, 0.400]
Zero inside interval: True
```

`delta` — B лучше A на 0.1 (два вопроса исправлены, один испорчен).
Интервал включает ноль: на этих данных нельзя утверждать улучшение.
Генератор создан с `seed=42`, поэтому числа повторяются от запуска к
запуску. Последняя строка `assert` проверяет, что версия, сравнённая сама
с собой, даёт нулевые разность и интервал.

Что доказывает и чего нет. Это расчёт на 10 выдуманных результатах. Он
показывает, насколько широк интервал на маленьком наборе, но ничего не
говорит о настоящих версиях.

Одно изменение. Вызови `paired_interval(a * 2, b * 2)` — те же строки,
скопированные дважды. Предскажи, станет ли интервал уже. Станет:
`[-0.15, 0.35]`, хотя новых вопросов нет. Это и есть ошибка из урока:
копия не независимое наблюдение. Затем допиши к `a` и `b` десять своих
новых вопросов и сравни.

## 03_judge_agreement.py — согласие судьи с человеком

После [урока 3](../01_theory/03_judges_and_release.md).

```bash
uv run python 7_evaluation_and_safety/02_examples/03_judge_agreement.py
```

Что делает. Списки `human` и `judge` — оценки одних и тех же 10 ответов
(1 — хороший, 0 — плохой). Настоящая модель-судья не вызывается: оценки
записаны заранее. Данные совпадают с ручным расчётом kappa в уроке.

Как читать вывод.

```text
confusion rows=human cols=judge: [[2 3]
 [0 5]]
agreement: 0.7
Cohen kappa: 0.4
Judge false approvals: 3
```

Матрица ошибок — как в [уроке о
метриках](../../2_classical_ml/01_theory/03_metrics.md): строки — оценка
человека (0, 1), столбцы — судьи. Верхняя строка `[2 3]`: из 5 плохих
ответов судья признал плохими 2, а 3 одобрил — это и есть 3 ложных
одобрения. Нижняя `[0 5]`: все хорошие ответы судья одобрил. Agreement 0.7
и kappa 0.4 совпадают с расчётом в уроке.

Что доказывает и чего нет. Видно, что одно число скрывает направление
ошибок: kappa 0.4 не говорит, что судья пропускает 3 из 5 плохих ответов.
Десять ответов слишком мало для решения о реальном судье.

Одно изменение. Исправь судью на одном плохом ответе: в `judge` замени
пятый элемент (индекс 4) на 0. Предскажи agreement, число ложных одобрений
и направление изменения kappa, затем запусти. Ожидаемо: agreement 0.8,
ложных одобрений 2, kappa вырастет.
