# AI Engineering Knowledge Base

Учебная база на русском: от первых понятий машинного обучения до разработки,
оценки и эксплуатации LLM-приложений. Основной маршрут — ML → нейросети → LLM →
поиск и RAG → оценка → дообучение → агенты → эксплуатация. CV и
мультимодальность дают возможность попробовать соседнюю специализацию.

Теория находится прямо в репозитории. Для начала нужен базовый Python: функции,
списки, словари, циклы, исключения и простейший класс — всё это с короткими
примерами собрано в [минимуме Python для курса](0_lab_setup/python_minimum.md).
Знания AI и высшей математики не предполагаются: математические определения
вводятся перед их использованием.

В текущей версии: 13 разделов, 54 последовательных урока теории со 174
вопросами самопроверки и отдельным блоком повторения на стыке разделов
(5 вопросов), 30 проверенных запуском CPU-примеров, 11 блоков самостоятельных
упражнений (22 программных задания), 3 итоговых проекта с критериями приёмки
и локальный HTTP-сервис. Ещё 6 примеров требуют вручную подготовленных весов:
без весов они проверены только на корректное сообщение об их отсутствии.

## Начать

1. Прочитать [старт и настройку](0_lab_setup/README.md).
2. Пройти [входную диагностику](0_lab_setup/03_exercises/README.md).
3. Открыть [порядок обучения](0_lab_setup/learning_path.md): в нём есть первое
   занятие и условия перехода между темами.
4. Внутри раздела следовать порядку уроков в его README: объяснение → ручной
   пример → самопроверка → лабораторная.
5. Сохранять свои эксперименты в `artifacts/`: конфигурация, метрики, выводы.
6. Итоговые проекты начинать по мере готовности: CPU-baseline классификатора
   обращений — после раздела 2, ассистент по документации — после 7,
   модельная часть классификатора — после 8, диагностический агент — после
   9–10.

Если пока не хочешь скачивать модели, следуй [маршруту без
весов](0_lab_setup/learning_path.md).

Все команды ниже и в разделах выполняются из корня этого репозитория. После
установки зависимостей один раз данные первых лабораторных доступны офлайн.
Модели не скачиваются автоматически. [Ссылки и ручная
подготовка](data/models.md).

```bash
uv sync --frozen                                        # поставить библиотеки
uv run python 0_lab_setup/02_examples/01_doctor.py      # проверить машину
uv run python 1_math_and_data/03_exercises/check.py     # проверить своё решение задания
```

`uv` — менеджер окружения и зависимостей, установка и объяснение — в
[уроке о среде](0_lab_setup/01_theory/02_hardware.md).

Что лежит в корне, кроме разделов:

- `data/` — учебные наборы данных и инструкция, где взять веса моделей;
- `other/` — шаблон отчёта об эксперименте, список источников и
  [словарь терминов](other/glossary.md) со ссылкой на урок, где каждый
  термин объяснён;
- `pyproject.toml`, `uv.lock`, `.python-version` — список библиотек с точными
  версиями и версия Python; по ним `uv sync` собирает окружение, руками не
  правятся;
- `artifacts/` — появляется локально: веса моделей и результаты твоих опытов,
  в Git не попадает.

Первый учебный запуск — после [урока о
градиенте](1_math_and_data/01_theory/02_gradients.md). В нём сначала вручную
рассчитывается, как исправить ошибку маленькой модели, а затем тот же принцип
проверяется в Python.

## Как читать материал

У каждого урока есть исходная задача. Например, раздел о выборе модели
начинается с вопроса: как понять, что классификатор справится с новым
обращением? Из этой задачи последовательно выводятся обучающая, настроечная и
тестовая выборки. LoRA начинается с необходимости изменить большую матрицу и
только затем вводит две маленькие матрицы и название метода.

Формулы сопровождаются объяснением обозначений и небольшими числами, которые
можно проверить вручную. Внешние статьи нужны для дальнейшего углубления;
базовое объяснение находится здесь. Необязательно понимать весь урок с первого
чтения: попробуй его пример, ответь на вопрос и после этого раскрой разбор.

## Формат и проверка знаний

- `01_theory/` — связные уроки: зачем нужна тема, как она работает, расчёт на
  маленьком примере и вопросы с раскрываемым разбором.
- `02_examples/` — законченные запускаемые эксперименты.
- `03_exercises/` — задания и исходники с `NotImplementedError`; это ожидаемое
  состояние.
- `04_exercises_answers/` — решения и объяснения для самопроверки.
- `README.md` — порядок конкретных уроков, связь с лабораторными и критерий
  перехода дальше.

Запуск примера не равен освоению темы. Сначала предскажи результат, затем
запусти, измени одно условие и объясни расхождение. В самостоятельных задачах
сначала работай без решений. Проверки функций дополняй отчётом о данных,
метриках и ошибках.

[Матрица компетенций и рубрика](12_capstones/01_theory/02_competencies.md)
описывает целевой уровень самостоятельности. Репозиторий даёт учебный маршрут и
практику; грейд middle определяется также опытом работы с реальными требованиями
и сбоями. Тяжёлые производственные эксперименты выделены в расширения, а не
изображаются CPU-симуляциями как якобы измеренные свойства больших систем.

## Ресурсы

Основной маршрут рассчитан на CPU и 16 ГБ RAM; для локальной модели и дообучения
рекомендуется 32–64 ГБ. Это проектные ориентиры, а не замеры на твоей машине.
Модель для первого запуска имеет 135 млн параметров:
она выбрана ради доступности экспериментов, её ответы не характеризуют качество
современных крупных моделей. Никакие платные API не обязательны.

Профили: **CPU** — без ускорителя; **MODEL** — CPU и заранее скачанная языковая
модель; **EMBEDDING** — CPU и заранее скачанная небольшая модель embeddings для
поиска по смыслу (в текстах примеров — «embedding»); **GPU extension** —
отдельные задания с ускорителем, не часть автоматической проверки. Intel Arc —
дополнительный путь ускорения; основной lock-файл устанавливает CPU PyTorch.
[Особенности Intel и Fedora](0_lab_setup/01_theory/02_hardware.md).
