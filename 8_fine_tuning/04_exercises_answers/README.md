## 1. `answer_labels`

Ход мысли. Метки — список той же длины, что вход после padding, и он
состоит из трёх кусков подряд: `-100` на каждый токен prompt, сами ID
ответа, `-100` на каждую позицию padding. Длину третьего куска
вычисляем: `pad_to - len(prompt) - len(answer)`. Поэтому решение — одно
сложение списков: `[-100] * len(prompt_ids) + list(answer_ids) + [-100] *
padding`.

Проверки входа идут до сборки: пустой ответ означал бы строку без
обучающего сигнала (все метки -100), а `pad_to` короче данных — что
обрезка уже съела часть ответа. Для ID используется `type(value) is
int`, а не `isinstance(value, int)`: `isinstance(True, int)` в Python
истинно, и `True` прошёл бы как токен 1.

Типичные ошибки:

- поставить `-100` вместо ID ответа, а ID — на prompt (перепутать, чему
  учим);
- вернуть список длиннее или короче `pad_to`: модель сравнивает метки с
  позициями входа один к одному, поэтому длины обязаны совпадать;
- сдвинуть метки на одну позицию самостоятельно: библиотека уже делает
  этот сдвиг, второй сдвиг учит модель угадывать токен через один.

## 2. `lora_parameters`

Ход мысли: A имеет форму `(r, d_in)`, B — `(d_out, r)`, значит параметров
`r × d_in + d_out × r = r × (d_in + d_out)`. Для урока: `4 × (128 + 64) =
768`. Bias и базовая матрица не входят: первый у A и B в LoRA обычно не
используется, вторая заморожена.

Типичные ошибки: посчитать `d_in × d_out` (это полная поправка, а не
адаптер); перепутать, что LoRA экономит: число обучаемых параметров
падает, но память базовых весов и активаций остаётся.

## 3. Сдвиг logits и labels

```text
позиция:        0     1     2   3   4     5     6
input_ids:    [ 5,    6,    7,  8,  9,  PAD,  PAD]
attention:    [ 1,    1,    1,  1,  1,    0,    0]
labels:       [-100,-100,-100,  8,  9, -100, -100]
```

| Выход позиции | Видела | Сравнивается с меткой позиции | В loss |
|---|---|---|---|
| 0 | `5` | 1: `-100` | нет |
| 1 | `5,6` | 2: `-100` | нет |
| 2 | `5,6,7` | 3: `8` | да |
| 3 | `5,6,7,8` | 4: `9` | да |
| 4 | `…,9` | 5: `-100` | нет |
| 5, 6 | padding | 6: `-100` / нет метки | нет |

Учатся ровно две позиции: предсказать 8 после инструкции и 9 после 8.
Если маскировать только padding, labels на позициях 1–2 стали бы `6, 7`,
и loss поощрял бы модель воспроизводить саму инструкцию — то, что в
работе ей всегда дают готовым. Если сдвинуть labels вручную, на позицию 2
придётся метка 9: модель штрафовали бы за то, что она не угадала токен
через один.

случаях. Для освоения темы также нужен твой письменный ответ на задание 3
и самостоятельный эксперимент из [примеров](../02_examples/README.md).
