# Примеры и эксперименты

Команды выполняются из корня репозитория после установки зависимостей.
Два примера из трёх (профиль **CPU**) не требуют весов и сети.
`02_train_adapter.py` (профиль **MODEL**) читает только локальные веса:
[где взять модели](../../data/models.md). Пока веса не подготовлены, он
завершается сообщением «Модель отсутствует» — это не успешный запуск.

Различай виды результата. **Расчёт** — проверка формул на заданных числах
(`01_lora_math.py`). **Синтетический опыт** — настоящее обучение, но на
придуманной задаче с известным ответом (`03_tiny_adapter.py`).
**Реальный эксперимент** — обучение настоящей LLM на учебных данных
(`02_train_adapter.py`); только его результат зависит от модели и может
не показать улучшения.

Для каждого опыта сначала запиши предсказание, затем измени одно условие и
сравни.

## 01_lora_math.py — формулы LoRA на числах

После урока [LoRA](../01_theory/03_lora.md). Профиль **CPU**, расчёт без
обучения.

```bash
uv run python 8_fine_tuning/02_examples/01_lora_math.py
```

Входные данные. Сначала — пример урока на двух числах: `w_small`
единичная, `x_small = [2, 3]`, `a_small` и `b_small` — те же A и B.
Затем случайные матрицы размеров из урока: W `(64, 128)`, r = 4, alpha =
8. Случайные значения здесь не важны: проверяются тождества, верные для
любых чисел.

Как читать вывод. `Lesson example output: [2.8 4.6]` — тот же общий выход,
что получен вручную в уроке. `Full matrix parameters: 8192 adapter
parameters: 768` — `64 × 128` против `4 × 128 + 64 × 4`. Вывод печатается
только после того, как прошли `assert`: при нулевой B выход равен
базовому; слить поправку в W или посчитать `B × (A × x)` отдельно — одно
и то же; ранг `B × A` не больше r.

Что доказывает: формулы урока и подсчёт параметров. Чего не доказывает:
ничего об обучении — A и B здесь не подбираются по данным.

Одно изменение. Поменяй `rank = 4` на `rank = 16`. Предскажи по формуле
`r × (d_in + d_out)`, сколько параметров покажет адаптер, и какую долю от
8192 это составит. Должно получиться `16 × 192 = 3072`, около 37%.
Если число другое, проверь, какие размеры ты подставил в формулу.

## 02_train_adapter.py — SFT с LoRA для настоящей модели

После уроков [подготовка данных](../01_theory/02_data_preparation.md) и
[LoRA](../01_theory/03_lora.md). Профиль **MODEL**: нужны веса
`artifacts/models/smollm2-135m` (около 260 MiB, ручное скачивание по
[инструкции](../../data/models.md)). Сеть во время запуска не нужна.

```bash
uv run python 8_fine_tuning/02_examples/02_train_adapter.py
```

Без весов скрипт сразу останавливается с сообщением «Модель отсутствует.
См. data/models.md». Этот путь проверен запуском; само обучение в курсе
запуском не проверялось, потому что веса в репозиторий не входят.

Входные данные — [`data/sft.json`](../../data/sft.json): 18 англоязычных
обращений с меткой `database`, `network` или `access`, 12 в train и 6 в
test. Что делает скрипт по шагам:

1. Жадно (без случайности) генерирует до 4 токенов ответа базовой модели
   на каждый test-запрос — это `before`.
2. Подключает LoRA с r = 4, alpha = 8 к `q_proj` и `v_proj` каждого слоя
   и печатает строку `trainable params: ... || all params: ...`.
3. 12 шагов (настраивается `--steps`) обучает только A и B, по одному
   train-примеру за шаг. Labels строит функция `training_example`: -100
   на позициях prompt, ID ответа и EOS — на остальных, как в уроке о
   [подготовке данных](../01_theory/02_data_preparation.md).
4. Сохраняет адаптер в `artifacts/adapter/`, загружает базу заново,
   подключает адаптер из файла и повторяет оценку — `after`.
5. Пишет `artifacts/adapter/experiment.json`: loss по шагам, время,
   ответы до и после, версии модели.

Как читать вывод. `base accuracy` и `adapter accuracy` — доля точных
совпадений ответа с меткой на 6 test-примерах; шаг значения — 1/6.
Изменение на одну-две задачи на таком наборе — не доказательство
улучшения или ухудшения. В отчёте смотри ответы по задачам и
`train_loss`: падение loss показывает подгонку к train, но не качество.

Перед повторным запуском перенеси или переименуй `artifacts/adapter/`:
скрипт не перезаписывает существующий адаптер и остановится с сообщением.
Не удаляй прошлый отчёт ради нового запуска.

Что доказывает: что адаптер обучается, сохраняется и загружается, и как
меняются ответы на этих 6 задачах. Чего не доказывает: что дообучение
полезно для задачи вообще, и ничего о QLoRA — база здесь не
квантуется. Результат не гарантирует улучшения.

Одно изменение. Сначала сравни строку `trainable params` с ручной
оценкой: для каждой из двух матриц на слой `r × (d_in + d_out)`, умножить
на число слоёв. Размеры возьми из `config.json` модели: `hidden_size` —
вход обеих проекций и выход `q_proj`; выход `v_proj` равен
`num_key_value_heads × hidden_size / num_attention_heads`; число слоёв —
`num_hidden_layers`. Затем, если хочешь менять настройки (`--steps`, r),
не выбирай их по test: выдели из train отдельный dev, иначе test
перестанет быть независимой проверкой.

## 03_tiny_adapter.py — настоящее обучение поправки без готовых весов

После урока [LoRA](../01_theory/03_lora.md). Профиль **CPU**,
синтетический опыт; PyTorch-конструкции (`nn.Module`, `nn.Parameter`,
оптимизатор) разобраны в [основах
PyTorch](../../3_neural_networks/01_theory/02_pytorch_basics.md).

```bash
uv run python 8_fine_tuning/02_examples/03_tiny_adapter.py
```

Входные данные — придуманная задача, где правильный ответ заранее
известен: базовая матрица W `(4, 8)` и поправка ранга 2. Правильные
ответы считаются как `(W + поправка) × x` для 160 случайных входов. Это
не данные урока: размеры маленькие, чтобы обучение заняло секунды.
`register_buffer` хранит W в модели без обучения — так она заморожена;
`self.a` и `self.b` — обучаемые A и B, B стартует с нулей. Учимся на
первых 120 строках, проверяем на 40 отложенных.

Как читать вывод. `Held-out MSE: 17.27... -> 2.8e-08` — среднеквадратичная
ошибка на отложенных строках до и после 200 шагов Adam: до обучения
модель равна базе и ошибается на всю поправку, после — почти точна.
Seed зафиксирован, поэтому на одной машине числа повторяются; на другой
могут отличаться в последних знаках. `base unchanged: PASS` печатается,
только если `assert` подтвердил, что W не изменилась и ошибка упала
больше чем в 20 раз.

Что доказывает: градиент обучает только A и B, а замороженная W остаётся
прежней; поправку низкого ранга можно найти по примерам. Чего не
доказывает: ничего о качестве дообучения LLM — у настоящей задачи нет
известной «правильной поправки ранга 2».

Одно изменение. Поменяй `adapter_rank = 2` на `adapter_rank = 1`, не
трогая `rank` (ранг нужной поправки). Предскажи: сможет ли адаптер
ранга 1 точно представить поправку ранга 2? На проверочной машине ошибка
останавливается около 0.78 вместо почти нуля. Обрати внимание: `PASS` при
этом всё равно печатается, потому что проверка требует только падения
ошибки в 20 раз, а не точного решения. Так выглядит ограничение
выразительности из урока: обучение идёт, но лучше определённого предела
стать не может.
