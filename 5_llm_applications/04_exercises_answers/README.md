# Разбор: Контракт ответа, стоимость вызова и память модели

Валидация схемы предотвращает нарушение интерфейса. Неверная метка с допустимым
значением всё равно пройдёт её, поэтому нужны размеченные примеры. Контекстный
бюджет вычисляется токенизатором конкретной модели; длина строки не равна числу
токенов.

Стоимость вызова считаем по трём ценам: свежий вход, вход из кэша и
выход. Закэшированные токены вычитаем из входа, а не прибавляем: иначе
одни и те же токены оплачивались бы дважды. Для 1500 входных, из них
1200 из кэша, и 200 выходных: `300 × 1 + 1200 × 0.1 + 200 × 4 = 1220`
миллионных долей, `0.00122` против `0.0023` без кэша. Словарь цен
проверяем строго: если ключа `cached_input` нет, функция не подставляет
цену «по умолчанию», а сообщает об ошибке. Тихая подстановка дала бы
правдоподобное, но неверное число в отчёте о расходах.

`wrap_untrusted` заменяет каждое `</ticket>` в данных на `</ ticket>`,
поэтому настоящий закрывающий тег остаётся ровно один — в конце. Текст
пользователя при этом сохраняется: молча выбрасывать его нельзя.
Ограничение на имя тега нужно, чтобы сам тег не содержал `<`, `>` или
`/`. Разделители — только подсказка модели, где данные: модель всё равно
может выполнить просьбу из текста. Защищает код вокруг неё — проверка
ответа, права доступа, список разрешённых действий.

Память весов: `params × bits / 8` байтов. 7B в FP16 — 14 GB, в Q8 — 7,
в Q4 — 3.5. Это нижняя граница: популярные варианты Q4 хранят масштабы
блоков и занимают около 4.5–5 бит на вес, а при запуске добавляются KV
cache, растущий с длиной контекста, и память самой программы.

[Код решения](solution.py). Из корня:

```bash
uv run python 5_llm_applications/03_exercises/check.py --answers
```

Эти проверки подтверждают контракт функций на граничных и обычных случаях. Для
освоения темы также нужен твой отчёт и самостоятельный эксперимент из задания.
