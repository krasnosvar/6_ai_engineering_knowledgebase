# Разбор: Контракт ответа, стоимость вызова и память модели

## parse_ticket и remaining_tokens

Ход мысли в `parse_ticket` повторяет слои из урока 1: сначала `json.loads`
(не JSON — он сам бросит `JSONDecodeError`, подкласс `ValueError`), затем
«это словарь ровно с двумя ключами» (`set(obj) == {'ticket_id', 'label'}`
отсекает и пропуск поля, и лишнее поле), затем типы и значения. Слой
смысла функция проверить не может: валидная, но неверная метка пройдёт,
поэтому нужны размеченные примеры (задание 3).

Типичные ошибки: искать `{...}` в прозе и «спасать» ответ; проверять
только наличие ключей, пропуская лишние; писать `obj['ticket_id']` до
проверки, что `obj` — словарь, — тогда на `'[]'` вылетит `TypeError`, а
не `ValueError`.

В `remaining_tokens` сначала проверяем все три входа, потом считаем
разность и отвергаем отрицательный остаток: тихо вернуть 0 значило бы
скрыть, что запрос не помещается. Сами числа токенов считает токенизатор
конкретной модели; длина строки не равна числу токенов.

## call_cost

Стоимость вызова считаем по трём ценам: свежий вход, вход из кэша и
выход. Закэшированные токены вычитаем из входа, а не прибавляем: иначе
одни и те же токены оплачивались бы дважды. Для 1500 входных, из них
1200 из кэша, и 200 выходных: `300 × 1 + 1200 × 0.1 + 200 × 4 = 1220`
миллионных долей, `0.00122` против `0.0023` без кэша. Словарь цен
проверяем строго: если ключа `cached_input` нет, функция не подставляет
цену «по умолчанию», а сообщает об ошибке. Тихая подстановка дала бы
правдоподобное, но неверное число в отчёте о расходах.

## wrap_untrusted

`wrap_untrusted` заменяет каждое `</ticket>` в данных на `</ ticket>`, поэтому
настоящий закрывающий тег остаётся ровно один — в конце. Текст пользователя при
этом сохраняется: молча выбрасывать его нельзя. Ограничение на имя тега нужно,
чтобы сам тег не содержал `<`, `>` или `/`. Типичная ошибка — отрезать всё, что
идёт после `</ticket>` в данных: так молча теряется текст пользователя;
`check.py` проверяет, что он сохранился. Разделители — только подсказка модели,
где данные: модель всё равно может выполнить просьбу из текста. Защищает код
вокруг неё — проверка ответа, права доступа, список разрешённых действий.

## weights_memory_gb

Память весов: `params × bits / 8` байтов. 7B в FP16 — 14 GB, в Q8 — 7,
в Q4 — 3.5. Это нижняя граница: популярные варианты Q4 хранят масштабы
блоков и на практике занимают больше 4 бит на вес (грубо 4.5–5, точнее
покажет размер файла), а при запуске добавляются KV cache, растущий с
длиной контекста, и память самой программы. Типичная ошибка — забыть
деление на 8 и получить биты вместо байтов, то есть ответ в 8 раз больше.

[Код решения](solution.py). Из корня:

```bash
uv run python 5_llm_applications/03_exercises/check.py --answers
```

Эти проверки подтверждают контракт функций на граничных и обычных случаях. Для
освоения темы также нужен твой отчёт и самостоятельный эксперимент из задания.
