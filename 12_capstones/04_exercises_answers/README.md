# Разбор архитектур и ориентиры ревью

Готового проекта для копирования нет: эти задания проверяют самостоятельное
решение. Используй ориентиры после первой реализации.

## Ассистент

Раздели ingestion, retrieval, сбор контекста и генерацию. Источник хранится
независимо от фрагмента. ACL входят в запрос поиска; индекс содержит версию.
Сначала локализуй, потерян ли документ при подготовке, ранжировании или сборке
контекста. Наличие цитаты не заменяет ручную проверку поддержки утверждения.
Отказ оценивается отдельно.

Оценку стоимости сверяй с usage из лога, а не только с формулой в отчёте:
заметное расхождение обычно значит, что забыты инструкция, история или
резерв на ответ. Бюджет контекста проверяй на самом длинном вопросе test.
Тест injection засчитывается, когда назван слой, остановивший атаку, и
объяснено, что случилось бы без него. «Модель отказалась» — слабое
свидетельство: следующая формулировка может пройти. Если есть судья, сначала
смотри калибровку: матрицу согласия и долю ложных одобрений, а не только
kappa; для парных сравнений — вердикты в обоих порядках. Отдельная векторная
база без измерения, что локальный индекс не справляется, — минус к
обоснованию, а не плюс за сложность.

## Маршрутизация

Простой ML может выигрывать по цене и задержке. Для LLM проверь, не связано ли
улучшение только с форматом ответов или пересечением шаблонов. Адаптер должен
сохраняться и загружаться с правильной базовой моделью. Решение по порогу отказа
выбирается на dev. Отдельно проверь новый класс и редкие ошибки. Учебный
HTTP-сервис не заменяет deployment и сохранение артефактов.

Цена решённого обращения включает ручной разбор, а не только вызовы модели.
Для каскада проверь, что доля эскалаций и итоговое качество измерены на test,
а не сложены из таблиц отдельных моделей. A/B prompt без стандартной ошибки
или парного сравнения не доказывает улучшения: разница в пару пунктов на
сотне примеров обычно в пределах шума.

## Агент

Наблюдаемое состояние песочницы важнее финальной фразы. Права определяются
исполнителем. Лимит шагов нужен даже для полностью корректного JSON. Долгая
история не заменяет структурированное состояние. Retry безопасен только при
определённых гарантиях операции.

Границу в стиле MCP оценивай по тестам: вызов вне allow-list отклонён до
исполнения, и это видно в trace. Открой trace одного сценария: по дереву
spans должно быть понятно, какой шаг привёл к диагнозу, а подложенный ключ
замаскирован. Многоагентная схема без подсчёта токенов и сравнения с одним
агентом на тех же сценариях не обоснована. Лимит памяти проверяется
сценарием, где сжатие срабатывает, а запрет из начала задачи соблюдается.

Для всех проектов: оцени по [рубрике](../01_theory/02_competencies.md), приложи
отчёт и проведи изменение требований без просмотра готового примера. При
отсутствии реального MODEL-запуска так и отметь; тест исполнителя не доказывает
качество агента.
