# Три итоговых проекта

Здесь нет `task.py` и `check.py`: итоговый проект проверяется не
готовыми тестами, а твоими данными, метриками и критериями приёмки,
которые ты записываешь до финального теста. Как это делать — в [уроке о
ходе проекта](../01_theory/01_project_workflow.md); как оценить
результат — в [рубрике](../01_theory/02_competencies.md).

## Какой проект и когда

| Проект | Можно начать | Что нужно для полной версии |
|---|---|---|
| [Маршрутизация обращений](02_ticket_routing.md) | CPU-baseline и сервис — после раздела 2 | эксперименты с LLM и SFT/LoRA — после раздела 8 и подготовки весов |
| [Ассистент по документации](01_document_assistant.md) | после раздела 7 | генерация ответа — модель с локальными весами или API |
| [Диагностический агент](03_diagnostic_agent.md) | после разделов 9–10 | агент на модели — веса или API; без них — workflow |

Проходи по одному. Если сомневаешься, с чего начать, начни с
маршрутизации: её первая версия целиком работает на CPU, а [учебный
сервис](../02_examples/README.md) — готовая отправная точка.

Модельные эксперименты выполняются после ручной подготовки весов по
[ссылкам](../../data/models.md). До этого модельную часть проекта нельзя
считать выполненной: в отчёте так и пиши — «не запускалось».

## Как устроен каждый проект

В начале каждого файла — таблица «Коротко»: когда браться, вход и выход,
данные, baseline, главные метрики, минимум приёмки и что можно отложить.
Дальше — подробные требования и полный список приёмки. Порядок работы
один для всех:

1. Заполни карточку проекта (пример — в [уроке о ходе
   проекта](../01_theory/01_project_workflow.md)).
2. Собери данные и раздели их до того, как смотреть на результаты.
3. Сделай baseline и проверь весь путь: данные → решение → метрика →
   сохранённый результат.
4. Добавляй по одной сложной части и сравнивай с baseline на dev.
5. Выполни финальный test один раз, затем «неожиданное изменение» из
   конца файла.

## Где хранить

Сохраняй проекты в `artifacts/projects/<name>/` для личной работы. Если
публикуешь портфолио, перенеси проверенные исходники в отдельный
Git-репозиторий, исключив секреты, скачанные веса и данные с
несовместимой лицензией. Готового решения в репозитории нет:
самостоятельная реализация — часть проверки навыка.

На каждый проект ориентируйся на 20–40 часов для первой версии и
дополнительное время на ошибки, изменения требований и защиту. Это
оценка, не лимит обучения. Выполненные проекты показывают, что ты умеешь
делать, но сами по себе не означают определённого грейда.

[Ориентиры для ревью](../04_exercises_answers/README.md) открывай после
первой реализации.
