# Начальный CPU-сервис

Настоящий локальный HTTP endpoint с TF-IDF-классификатором. Веса LLM не
требуются.

Термины на этой странице:

- **endpoint** — адрес внутри сервиса, по которому принимается один вид
  запросов: `/health` и `/classify`;
- **curl** — консольная программа, которая отправляет HTTP-запрос и печатает
  ответ; здесь она играет роль клиента;
- **loopback** (`127.0.0.1`) — адрес «этот же компьютер»; сервис на нём
  недоступен из сети, только локально;
- **ingress** — входной слой перед публичным сервисом (балансировщик или
  прокси), который ограничивает число и размер запросов до того, как они
  дойдут до приложения;
- **Content-Type** — заголовок запроса, сообщающий формат тела; сервис
  принимает только `application/json`;
- **коды ответа**: 200 — успех; 400 — неверный запрос (например, пустой `text`);
  404 — такого endpoint нет; 408 — клиент слишком долго передавал запрос; 413 —
  тело запроса больше допустимого; 415 — неподдерживаемый Content-Type. Коды
  200, 400, 401, 429 и 5xx разобраны в [уроке о контракте
  вызова](../../5_llm_applications/01_theory/02_runtime_contract.md).

Запуск из корня в первом терминале:

```bash
uv run python 12_capstones/02_examples/01_ticket_service.py
```

Во втором:

```bash
curl http://127.0.0.1:8080/health
curl -H 'Content-Type: application/json' --data '{"text":"database connection refused"}' http://127.0.0.1:8080/classify
```

Ожидаются JSON со `status=ok` и JSON с `label=database`,
`version=tfidf-demo-v1`. Проверь пустой text (400), неизвестный endpoint (404)
и неправильный Content-Type (415). Останови сервер Ctrl+C. Порт 8080 должен
быть свободен; можно выбрать `--port 8081`.

Это учебный сервис на loopback, не публичный production endpoint. Ограничены
тело, время чтения и параллельные вычисления, но не число создаваемых
HTTP-потоков; публичному сервису нужны ingress-лимиты и полноценная
авторизация. Модель переобучается при старте; проект требует сохранения и
версионирования артефакта.
