# Начальный CPU-сервис

## 01_ticket_service.py — локальный HTTP-сервис классификации

Читай после [урока о ходе проекта](../01_theory/01_project_workflow.md);
устройство сервиса заранее разобрано в [уроке об
обслуживании](../../10_serving_and_operations/01_theory/01_serving_basics.md).
Профиль **CPU**: веса LLM и сеть не нужны.

Идея: показать baseline проекта маршрутизации как настоящий сервис —
модель загружается один раз при старте, а запросы приходят по HTTP и
проверяются до того, как дойдут до модели.

Термины на этой странице:

- **endpoint** — адрес внутри сервиса, по которому принимается один вид
  запросов: `/health` и `/classify`;
- **curl** — консольная программа, которая отправляет HTTP-запрос и
  печатает ответ; здесь она играет роль клиента;
- **loopback** (`127.0.0.1`) — адрес «этот же компьютер»; сервис на нём
  недоступен из сети, только локально;
- **ingress** — входной слой перед публичным сервисом (балансировщик или
  прокси), который ограничивает число и размер запросов до того, как они
  дойдут до приложения;
- **Content-Type** — заголовок запроса, сообщающий формат тела; сервис
  принимает только `application/json`;
- **коды ответа**: 200 — успех; 400 — неверный запрос (например, пустой
  `text`); 404 — такого endpoint нет; 408 — клиент слишком долго
  передавал запрос; 413 — тело запроса больше допустимого; 415 —
  неподдерживаемый Content-Type; 429 — сервис занят. Коды 200, 400, 401,
  429 и 5xx разобраны в [уроке о контракте
  вызова](../../5_llm_applications/01_theory/02_runtime_contract.md).

Сам HTTP-сервер построен на стандартной библиотеке Python (`http.server`):
сервер создаёт объект `Handler` на каждый запрос и вызывает его метод `do_GET`
или `do_POST`. Что такое класс и метод — в [уроке о
классах](https://github.com/krasnosvar/4_python_my_knowledgebase/blob/main/1_python/3_oop/01_theory/01_what_is_a_class.md),
что такое HTTP-запрос — в [уроке об
HTTP](https://github.com/krasnosvar/4_python_my_knowledgebase/blob/main/3_web_frameworks/1_fastapi/01_theory/01_http_and_first_app.md).

## Входные данные

При старте сервис читает `data/tickets.json`: 18 коротких английских
обращений трёх классов (`database`, `network`, `access`), из них 12 с
пометкой `train`. На них обучается TF-IDF + логистическая регрессия из
[раздела 2](../../2_classical_ml/README.md). Остальные 6 (`test`) сервис
не использует — на них можно проверить его ответы самостоятельно.

## Запуск и проверка

В первом терминале, из корня репозитория:

```bash
uv run python 12_capstones/02_examples/01_ticket_service.py
```

Сервис печатает `Listening on http://127.0.0.1:8080` и ждёт запросов.
Если порт 8080 занят (ошибка `Address already in use`), выбери другой:
`--port 8081`, и подставь его в команды ниже.

Во втором терминале:

```bash
curl http://127.0.0.1:8080/health
curl -H 'Content-Type: application/json' --data '{"text":"database connection refused"}' http://127.0.0.1:8080/classify
curl -i http://127.0.0.1:8080/nope
```

Ожидаемые ответы:

- `{"status": "ok", "version": "tfidf-demo-v1"}` — сервис готов;
- `{"label": "database", "version": "tfidf-demo-v1"}` — класс и версия
  решения, которое его выдало;
- статус `404` и `{"error": "not_found"}` — флаг `-i` печатает строку
  статуса вместе с заголовками.

Проверь и ошибки входа: пустой `text` (`--data '{"text":" "}'`) даёт
400, запрос без заголовка `Content-Type` — 415. Останови сервер Ctrl+C в
первом терминале.

## Что доказывает и чего нет

Доказывает: весь путь «запрос → проверка → модель → ответ с версией»
работает, а плохой вход получает понятную ошибку, а не падение
процесса. Ограничены размер тела (8192 байта), длина текста (2000
символов), время чтения запроса (5 секунд) и число одновременных
классификаций (2; лишние получают 429).

Не доказывает качество: шесть проверочных обращений слишком мало, и у
модели нет отказа — на любой текст, даже «погода хорошая», она выберет
один из трёх классов. Это учебный сервис на loopback, не публичный
production endpoint: не ограничено число создаваемых HTTP-потоков, нет
авторизации; публичному сервису нужны ingress-лимиты и полноценная
авторизация. Модель переобучается при каждом старте; в проекте её нужно
сохранять и версионировать.

## Одно изменение

Отправь на `/classify` текст, не относящийся ни к одному классу,
например `"the weather is nice today"`. Предскажи заранее: вернёт ли
сервис ошибку? Нет — придёт один из трёх классов с кодом 200. Это и есть
первое требование проекта маршрутизации: добавить порог уверенности
(`predict_proba` в scikit-learn) и ответ «на ручной разбор», если
уверенность ниже порога. Порог выбирай на dev, а не на глаз.
