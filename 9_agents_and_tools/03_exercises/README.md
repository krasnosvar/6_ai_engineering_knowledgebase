## Где писать и как проверять

Решения пиши в [`task.py`](task.py): там уже есть все пять функций,
внутри каждой стоит `raise NotImplementedError`. Замени эту строку своим
кодом. Проверка из корня репозитория:

```bash
uv run python 9_agents_and_tools/03_exercises/check.py
```

`check.py` проверяет функции по порядку заданий. Пока очередная функция
не написана, он останавливается на `NotImplementedError: TODO: ...` — это
ожидаемо и означает «здесь ещё нет решения»; можно решать по одной
функции и запускать проверку после каждой. Если код возвращает не то
значение, увидишь `AssertionError` с номером строки в `check.py`: открой
её и сравни ожидание со своим результатом. Когда всё верно, печатается
`PASS: 9_agents_and_tools student`.

Часть проверок требует, чтобы на неверных входах функция поднимала
`ValueError('описание')`: так функция сообщает «мне дали неверные данные» и
останавливается. Если исключения ещё не знакомы — урок
[исключения](https://github.com/krasnosvar/4_python_my_knowledgebase/blob/main/1_python/1_python_fundamentals/07_exceptions/01_theory/01_exceptions.md)
в Python-базе.

## 1. Проверка действия: `validate_action`

Дано: `action` — то, что предложила модель после `json.loads`, в формате
урока: `{'tool': 'read_metrics', 'arguments': {'service': 'demo'}}`.

Сделать: `validate_action(action)` возвращает `arguments`, только если
`action` — словарь ровно с ключами `tool` и `arguments`,
`tool == 'read_metrics'`, а `arguments` — словарь ровно с одним ключом
`service`, равным `'demo'`. Всё остальное — `ValueError`: чужой
инструмент, чужой сервис, лишнее поле, не словарь. Ни `eval`, ни shell
применять нельзя (почему — в [уроке](../01_theory/01_tool_calling.md)).

## 2. Бюджет и отмена: `may_continue`

Дано: `steps` — сколько шагов уже сделано, `limit` — лимит шагов,
`cancelled` — отменил ли пользователь задачу.

Сделать: `may_continue(steps, limit, cancelled)` возвращает `True`, только
если `steps < limit` и `cancelled` равно `False`. `ValueError`, если
`steps` не целое или отрицательное, `limit` не целое или меньше 1,
`cancelled` не `bool`.

## 3. Письменно: timeout изменяющего действия

Агент вызвал «перезапустить сервис» и получил timeout. Опиши по шагам,
что делать дальше, используя состояния из урока. Объясни, почему
неизвестный исход не равен «эффекта не было», что изменится, если повтор
придёт с новым ID операции, и что — при двух одновременных вызовах и
рестарте процесса с журналом из `03_idempotency.py`.

## 4. Ответ хоста в стиле MCP: `handle_jsonrpc`

Дано:

- `request` — словарь JSON-RPC запроса, как в уроке:
  `{'jsonrpc': '2.0', 'id': 1, 'method': 'tools/list'}` или
  `{'jsonrpc': '2.0', 'id': 2, 'method': 'tools/call', 'params': {'name':
  'read_metrics', 'arguments': {'service': 'demo'}}}`;
- `tools` — словарь «имя → функция»: то, что умеет сервер. Функция
  принимает словарь `arguments` и возвращает текст или поднимает
  `ValueError`, если не смогла выполнить работу;
- `allowed` — множество имён, разрешённых политикой хоста.

Сделать: `handle_jsonrpc(request, tools, allowed)` возвращает ответ
`{'jsonrpc': '2.0', 'id': <id запроса>}` плюс либо `result`, либо
`error` вида `{'code': ..., 'message': ...}`. Правила по порядку:

- `tools/list` → `result` `{'tools': [...]}`: отсортированный список
  имён, которые есть и в `tools`, и в `allowed`. Упрощение задания: в
  настоящем MCP в списке объекты со схемой `inputSchema`, здесь — только
  имена;
- `tools/call` без строки `name` или словаря `arguments` в `params` →
  error `-32602`, `'Invalid params'`;
- имя не в `allowed` → error `-32000`, `'Tool not allowed'`; функцию при
  этом не вызывать — `check.py` считает реальные вызовы;
- разрешено, но нет в `tools` → error `-32602`, `'Unknown tool'`;
- функция вернула текст → `result` `{'isError': False, 'content':
  [{'type': 'text', 'text': текст}]}`; функция подняла `ValueError` → то
  же с `'isError': True` и текстом ошибки `str(exc)`;
- любой другой метод → error `-32601`, `'Method not found'`.

`ValueError` (а не ответ с `error`) ожидается, если сам запрос неверной
формы: не словарь, `jsonrpc` не `'2.0'`, нет ключа `id`, `method` не
строка, `params` есть, но не словарь. Это ошибка кода, который собрал
запрос, а не ситуация для модели.

## 5. Цена одного и нескольких агентов: `agent_tokens`, `multi_agent_cost`

Дано: `system` — токены инструкции, `per_step` — сколько токенов
наблюдения добавляет каждый шаг, `steps` — число шагов; для нескольких
агентов ещё `workers` — число исполнителей и `summary` — токены одной
сводки.

Сделать:

- `agent_tokens(system, per_step, steps)` — входные токены одного агента
  по формуле урока: на шаге i (с нуля) модель читает `system + per_step ×
  i`, ответ — сумма по всем шагам;
- `multi_agent_cost(system, per_step, steps, workers, summary)` —
  `workers` исполнителей по `steps` шагов плюс два вызова оркестратора:
  план (`system`) и итог (`system` и `workers` сводок по `summary`).

Все аргументы — положительные целые, иначе `ValueError`; `True`/`False`
и дробные числа тоже не подходят. Проверь себя на числах урока: 19500,
112500, 63400. Затем найди, при каком числе областей (`workers`, у
одного агента `6 × workers` шагов) оркестратор становится дешевле одного
агента.
