# Разбор: Безопасный исполнитель

Модель только предлагает действие. Исполнитель проверяет его вне модели и не
расширяет права по тексту запроса. После неопределённого результата внешней
операции нужна проверка её статуса по ID; слепой повтор без идемпотентности
может дублировать эффект.

`handle_jsonrpc` сначала проверяет форму запроса: неверный запрос — ошибка
вызывающего кода, поэтому `ValueError`, а не ответ. Дальше порядок
проверок важен. `tools/list` возвращает пересечение того, что умеет
сервер, и того, что разрешил хост: модель не должна даже узнать о
`restart_service`. В `tools/call` политика хоста проверяется раньше
поиска инструмента, и запрещённая функция не запускается вовсе — это
проверяет счётчик вызовов в `check.py`. Различай два вида неудачи:
`ValueError` внутри инструмента превращается в `result` с
`isError: True` (модель прочитает текст и может исправить аргументы), а
неизвестный метод или инструмент — в поле `error` с кодом, которое
обрабатывает код хоста. Прочие исключения инструмента решение не глушит:
это ошибка программы, а не ответ для модели.

`agent_tokens` — формула урока: на шаге `i` читается `system + per_step ×
i`, а сумма `0 + 1 + ... + (n − 1)` равна `n × (n − 1) / 2`. Деление
нацело точное, потому что из двух соседних чисел одно чётное.
`multi_agent_cost` складывает исполнителей и два вызова оркестратора:
`3 × 19500 + 2000 + 2900 = 63400`. Сравнение с одним агентом на `6 ×
workers` шагов: при `workers = 1` оркестратор дороже (`19500 + 2000 +
2300 = 23800` против 19500), при `workers = 2` уже дешевле (`39000 + 2000
+ 2600 = 43600` против `2000 × 12 + 500 × 66 = 57000`). Выигрыш даёт не
деление само по себе, а то, что история каждого исполнителя короче.

освоения темы также нужен твой отчёт и самостоятельный эксперимент из задания.
