# Как дать модели инструменты

Некоторые задачи требуют действия: запросить метрику или получить данные
через функцию. Разделим предложение модели и исполнение программы. Затем
рассмотрим, как сохранить смысл операции при повторе запроса и ограничить
многошаговую работу, как подключать внешние инструменты через MCP и когда
задаче нужно несколько агентов.

Перед этим разделом: [Когда и как дообучать модель](../8_fine_tuning/README.md).

## Порядок чтения

1. [От фиксированного процесса к агенту](01_theory/01_tool_calling.md) —
   выбор инструмента, проверка аргументов и цикл действий.
2. [Что делать после обрыва связи](01_theory/02_state_and_retries.md) —
   состояние операции, повторяемость и журнал выполнения.
3. [Как подключать инструменты через MCP](01_theory/03_mcp.md) — host,
   client и server, JSON-RPC, транспорты, полномочия и риски.
4. [Когда нужно несколько агентов](01_theory/04_multi_agent_and_memory.md)
   — orchestrator–worker, цена, сбои, память агента, агенты для кода.

Читай уроки последовательно. Перед раскрытием разбора ответь на вопросы
самопроверки своими словами; если объяснение пока не получается, вернись к
разобранному примеру.

## Как перейти к практике

Выполни 01_executor.py и 03_idempotency.py. Они показывают исполнение и
повторы в маленькой локальной программе. 04_mcp_toy.py показывает обмен
сообщениями в стиле MCP между клиентом и сервером. 02_model_tool.py после
подготовки весов добавит выбор одного инструмента моделью; полный
многошаговый агент — самостоятельное расширение.

Все команды выполняются из корня репозитория.
[Инструкция к примерам](02_examples/README.md) содержит команды и ожидаемые
результаты. Затем открой [самостоятельные задания](03_exercises/README.md);
[ответы и разбор](04_exercises_answers/README.md) используй после своей
попытки.
