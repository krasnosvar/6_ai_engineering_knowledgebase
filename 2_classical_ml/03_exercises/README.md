# Метрики редкого класса и утечка через группы

Профиль CPU, нужна только стандартная библиотека Python; 1–2 часа. Два
задания программируются в [task.py](task.py), третье — письменное
рассуждение и небольшой опыт.

## 1. `binary_metrics(truth, pred)`

**Тема:** [урок о метриках](../01_theory/03_metrics.md) — TP, FP, FN,
precision, recall, F1.

**Дано:** два списка одинаковой длины из 0 и 1: `truth` — правильные метки,
`pred` — ответы модели. Положительный класс — 1 (например, «авария»).

**Сделать:** вернуть словарь `{'precision': ..., 'recall': ..., 'f1': ...}`.
Если знаменатель метрики равен 0 (например, модель не выдала ни одной
единицы), значение — `0.0`, а не деление на ноль.

**Ошибки входа:** поднять `ValueError` (`raise ValueError('текст')`), если
списки пустые, разной длины или содержат что-то кроме 0 и 1. Проверка вызывает
функцию с такими входами и ждёт именно `ValueError`.

Пример для самопроверки вручную: `truth=[1,1,0,0]`, `pred=[1,0,1,0]` дают
TP=1, FP=1, FN=1, поэтому все три метрики равны 0.5.

## 2. `group_overlap(train_groups, test_groups)`

**Тема:** [урок о разделении данных](../01_theory/02_model_selection.md),
раздел об утечке, и пример `02_leakage.py`.

**Дано:** два списка ID групп (например, клиентов) — по одному на строку train
и test; ID могут повторяться.

**Сделать:** вернуть множество (`set`) ID, которые встречаются в обоих
списках. Пустое множество означает, что пересечения групп нет.

## 3. Письменно: цена ошибок и сравнение признаков

1. На 99 отрицательных и одном положительном примере посчитай accuracy и
   recall классификатора, который всегда отвечает 0. Объясни, чего стоит такой
   классификатор для аварийных обращений.
2. Дополнительно: в копии `01_tickets.py` выдели dev из 12 train-обращений
   (например, по одному обращению каждого класса) и сравни на нём словесный
   `TfidfVectorizer()` и символьный `TfidfVectorizer(analyzer='char_wb',
   ngram_range=(2, 4))`. Встроенный test используй один раз — для итоговой
   проверки выбранного варианта. Запиши, почему разница на трёх
   dev-обращениях ещё не доказывает превосходство одного варианта.

## Как проверить

Пиши решение в `task.py`, не меняя имена функций. Затем из корня репозитория:

```bash
uv run python 2_classical_ml/03_exercises/check.py
```

- До решения проверка падает с `NotImplementedError: TODO: precision, recall,
  f1` — это заготовка `raise NotImplementedError` в `task.py`, а не ошибка
  установки.
- `AssertionError` с номером строки `check.py` означает, что результат
  отличается от ожидаемого: открой эту строку и сравни вход и ожидание.
- `AssertionError: Expected ValueError` — функция не отвергла неверный вход.
- Всё верно, когда в конце печатается `PASS: 2_classical_ml student`.
